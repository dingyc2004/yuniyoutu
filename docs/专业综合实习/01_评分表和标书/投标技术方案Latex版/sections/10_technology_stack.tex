\subsection{前端选型理由}

前端采用 Vue 3 + Vite。Vue 组件模型清晰、学习成本适中、生态成熟，适合构建地图首页、钓点详情、社区信息流、发布表单、出钓记录、教程列表、服务页和个人报告等页面。Vite 提供快速构建和模块化开发能力，便于团队在页面交互、地图组件和 API 调用之间保持清晰边界。

Element Plus 用于基础控件和交互组件，能够减少重复开发，使页面风格、表单校验、弹窗交互和状态提示保持一致。地图类页面由高德 JS API 承接，普通业务页面由 Vue 组件承接，二者通过统一状态和 API 服务层协作。

\subsection{后端选型理由}

后端采用 FastAPI。FastAPI 与 Pydantic 结合后，可以直接定义 POI、记录、帖子、推荐、天气、用户偏好等模型，接口参数和响应结构清晰，适合投标文件、接口文档和代码实现保持一致。Python 生态对规则模型、统计分析、AI API 调用和数据处理友好，能够支撑推荐解释的快速迭代。

后端分为 API 路由层、业务服务层、数据访问层和第三方服务封装层。API 路由层处理 HTTP 请求和参数校验；业务服务层承接推荐、记录、社区、报告、活动和订单演示逻辑；当前数据访问层通过 \texttt{json\_store.py} 操作 JSON 集合；第三方封装层统一接入高德和 DeepSeek，并在服务不可用时返回可演示的降级结果。

\subsection{数据层选型理由}

当前课程 MVP 采用 JSON 集合，是为了降低部署门槛、便于评审检查数据内容、保证单机演示稳定。每个集合配套 \texttt{.schema.json}，能够直接说明字段含义；原子写入策略能够保证新增记录、帖子、评论、活动报名和订单演示在服务重启后不丢失。

JSON 集合不适合作为正式多人并发数据库。因此，正式工程化阶段应迁移到 PostgreSQL/PostGIS，并将图片、视频和报告长图迁移到对象存储。这样的表述既说明本期系统如何运行，也明确后续扩展边界。

\subsection{AI 与推荐选型理由}

推荐系统采用规则模型与 AI 解释分工协作。规则模型负责可解释排序、合规拦截和风险降权，避免推荐结果不可验证；AI 负责解释推荐原因、结合用户偏好生成出钓建议和复盘建议。该设计既能体现智能化服务能力，也能保证合规、安全和可审计。

DeepSeek API 用于自然语言生成。后端只向大模型传递结构化上下文和授权画像摘要，不传递完整隐私原文。大模型输出必须经过格式校验和风险约束，不允许直接覆盖规则排序结果。
