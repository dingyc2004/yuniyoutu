\section{附录}

本附录用于汇总第3份涉及的交付物、部署配置、验收指标、角色分工、培训维护和点对点响应摘录，便于后续整理为 Word 版《技术投标文件》时直接作为附件或表格引用。样例技术规范书要求技术资料全面、完整、详细，包括软件系统、源代码及说明书、实施方案、需求规格说明书、UI 设计原稿、概要设计、详细设计、数据库设计、接口设计、系统测试方案、测试用例、测试报告、操作手册、部署说明、培训方案、项目管理文档、第三方测试报告和安全风险评估报告等；同时要求项目结束后移交全部技术文档。本项目附录据此设置，不仅服务课程提交，也尽量贴近真实技术投标文件格式。

\subsection{附录A：项目交付物清单}

本期课程交付包括：

\begin{itemize}
  \item 一套可运行软件系统（含地图首页、钓点详情、推荐解释、鱼获记录、社区信息流、教程页、我的页面、会员报告、活动服务和订单演示等模块）
  \item 一套前端源代码
  \item 一套后端源代码
  \item 一份源代码说明书（说明目录结构、启动方式、环境变量、主要接口、模拟数据和第三方服务 mock 方式）
  \item 一份部署说明（分别覆盖本地运行和服务器部署，至少写明后端 Python 版本、依赖安装、前端 Node 版本、构建命令、运行命令、\texttt{.env} 配置、测试账号和常见问题）
  \item 一份系统操作手册
  \item 一份接口说明
  \item 一份数据库或 JSON 集合字段说明
  \item 一份系统测试方案
  \item 一份系统测试用例
  \item 一份系统测试报告（包含测试范围、测试环境、测试用例、通过情况、缺陷列表、性能结果和安全自查结论）
  \item 一份项目实施计划
  \item 一份风险清单
  \item 一份培训材料
  \item 一份演示视频
  \item 一份技术评分表
  \item 一份技术投标文件
\end{itemize}

\subsection{附录B：环境变量与配置项示例}

后端配置包括 \texttt{APP\_ENV}、\texttt{BACKEND\_HOST}、\texttt{BACKEND\_PORT}、\texttt{DATABASE\_URL}、\texttt{REDIS\_URL}、\texttt{AMAP\_JS\_API\_KEY}、\texttt{AMAP\_SECURITY\_CODE}、\texttt{AMAP\_WEB\_SERVICE\_KEY}、\texttt{DEEPSEEK\_API\_KEY}、\texttt{OBJECT\_STORAGE\_ENDPOINT}、\texttt{OBJECT\_STORAGE\_BUCKET}、\texttt{JWT\_SECRET}、\texttt{LOG\_LEVEL} 等。

课程演示阶段可以将数据库配置替换为 JSON 数据目录，将对象存储替换为本地上传目录，将 AI Key 留空并启用 mock；正式阶段则必须使用真实数据库、对象存储、HTTPS 域名和后端密钥管理。前端配置包括 API 基础地址、构建模式、地图容器配置、静态资源路径和错误上报地址。

所有真实密钥不得进入 Git 仓库，提交时只提供 \texttt{.env.example}，真实 \texttt{.env} 由部署人员在服务器配置。

\subsection{附录C：核心验收指标}

功能完整性方面，地图找点、钓点详情、规则推荐、鱼获记录、社区发布、教程学习、个人报告、活动报名、活动签到和订单演示均应具备可演示路径。

数据完整性方面，一次出钓记录至少包含用户、钓点、时间、天气、鱼种、数量或重量、钓法、可见性和复盘字段；社区帖子与记录关联时应保留 \texttt{record\_id} 或等价关联字段。

性能方面，课堂演示环境中核心页面应能稳定打开，普通接口响应小于 2 秒，推荐接口小于 3 秒；正式工程指标为 100 并发请求、交互响应时间小于等于 2 秒、模型调度时间小于 3 秒等要求。

安全方面，第三方 Key 不得出现在前端代码，用户位置展示必须受权限控制，上传文件必须限制格式，日志不得记录明文密码和完整精确位置。

文档方面，部署说明、测试报告、接口说明和操作手册必须能支撑老师或评审人员复现系统。

\subsection{附录D：项目角色分工}

\begin{itemize}
  \item \textbf{项目经理}：负责进度、会议、风险、验收和最终汇总
  \item \textbf{产品经理}：负责需求分析、功能响应、原型设计和用户链路
  \item \textbf{技术经理}：负责总体架构、接口边界、代码规范和第三方服务接入
  \item \textbf{前端工程师}：负责 Vue/Uni-app 页面、地图交互、移动端适配和前端状态管理
  \item \textbf{后端工程师}：负责 FastAPI、数据接口、推荐服务、权限校验和日志
  \item \textbf{数据与推荐工程师}：负责 POI 字段、鱼情规则、报告统计和 AI 解释约束
  \item \textbf{测试工程师}：负责测试方案、测试用例、缺陷跟踪、性能测试和安全自查
  \item \textbf{文档工程师}：负责技术投标文件、部署说明、操作手册、培训材料和演示脚本
\end{itemize}

当小组人数不足时，一人可兼任多个角色，但在文档中仍应明确职责边界，便于老师评价团队协作情况。

\subsection{附录E：培训与维护安排}

培训对象包括普通用户、平台管理员和技术维护人员。

普通用户培训重点为地图找点、查看推荐、记录鱼获、设置位置权限、发布社区、查看报告和参加活动；管理员培训重点为钓点数据维护、帖子审核、活动管理、用户反馈处理、演示数据恢复和常见故障处理；技术维护人员培训重点为代码结构、环境变量、部署命令、日志查看、数据库备份、第三方 Key 配置和版本回滚。

培训方式可采用 1 次集中讲解、1 次上机演示和 1 份操作手册。维护期内，项目组提供问题响应、缺陷修复、数据备份指导和必要的版本升级说明。样例技术规范书中要求技术支持和培训覆盖系统性能、结构原理、使用操作、安装调测、故障排除等内容，并提供维护期间技术支持；本项目课程版可将其落实为操作手册、部署说明和答疑记录。

\subsection{附录G：演示数据与验收脚本}

演示账号至少准备普通用户、会员用户、管理员用户三类；演示钓点至少包含公开收费钓场、城市湖泊、野钓水域、禁钓风险水域四类；演示帖子至少包含鱼获、空军复盘、探点、教程心得四类；演示记录至少包含不同天气、不同鱼种、不同钓法和不同位置权限；演示活动至少包含可报名、已报名、已签到、已结束四种状态；演示订单至少包含待支付、已支付、已取消三种状态。

演示脚本按 8 分钟控制：
\begin{enumerate}
  \item 第 1 分钟：展示地图和钓点详情
  \item 第 2 分钟：展示推荐解释和风险提示
  \item 第 3 分钟：展示开竿与收竿记录
  \item 第 4 分钟：展示个人主页和会员报告
  \item 第 5 分钟：展示一键发布社区
  \item 第 6 分钟：展示教程推荐
  \item 第 7 分钟：展示活动报名和签到
  \item 第 8 分钟：展示订单演示、部署说明和测试报告
\end{enumerate}

当现场时间不足，优先保留地图、推荐、记录、报告和社区五个主链路，不临时展示尚不稳定的支付、实时聊天或监管端能力。

\subsection{附录H：术语说明}

\begin{itemize}
  \item \textbf{POI}：兴趣点（Point of Interest），在本项目中主要指钓点、水域、钓场、渔具店、停车点等空间对象
  \item \textbf{垂钓语义增强 POI}：在普通地理位置基础上增加鱼种、钓法、规则、收费、鱼情、设施和用户记录等垂钓字段
  \item \textbf{鱼情分}：结合近期鱼获、目标鱼种、季节和钓友反馈形成的评分
  \item \textbf{合规分}：结合禁钓、限钓、规则来源和安全风险形成的评分
  \item \textbf{天气适配分}：结合温度、风力、降水、气压、潮汐等条件形成的评分
  \item \textbf{结构化社区}：帖子与真实出钓记录、钓点、天气、鱼种和钓法等字段关联，而不是单纯图文信息流
  \item \textbf{会员报告}：基于用户历史出钓数据生成的月报、年报或生涯报告
  \item \textbf{位置模糊化}：根据用户权限设置降低坐标精度，只展示大致范围或行政区划，保护用户私密钓点
\end{itemize}

以上术语在投标文件首次出现时统一说明，避免评审人员将平台误解为普通地图、普通论坛或单纯 AI 聊天工具。
