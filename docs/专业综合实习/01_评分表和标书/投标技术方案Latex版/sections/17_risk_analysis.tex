\section{风险分析与应对措施}

本项目风险分析按照"数据风险、技术风险、进度风险、安全合规风险、第三方服务风险、用户内容风险、商业闭环风险、验收风险"八类展开。课程 PPT 中关于招投标注意事项强调评分机制应减少主观项，技术评分要细化到可核查证据点，同时付款节点与验收标准应在招标文件阶段明确，以减少后续争议。因此，本章不写笼统的"加强管理、积极应对"，而是对每类风险说明触发条件、影响范围、预防措施、应急措施和验收证据，使风险管理能够进入项目实施计划和技术评分表。

\subsection{钓点与规则数据风险}

鱼你有图的核心功能依赖钓点 POI、禁钓规则、常见鱼种、近期鱼获和天气水情等数据。如果钓点数据过少、字段不完整、规则过期或来源不明，用户就无法信任推荐结果。当前 MVP 阶段 POI 主要来自 JSON 演示集合，适合课程展示，但仍需要在字段中说明来源、更新时间、可钓状态和风险标签；用户共建、纠错、审核与可信度评分属于后续增强。

预防措施是建立 POI 数据字段规范，至少包含名称、坐标、类型、来源、更新时间、可钓状态、风险标签和审核状态；对禁钓规则明确来源链接、发布日期、适用范围和更新时间；对用户贡献钓点设置待审核状态，未经审核不得作为强推荐依据。应急措施是当规则数据不确定时，系统不输出"允许垂钓"的确定性结论，只输出"请以现场公告和主管部门规定为准"的风险提示，并降低推荐权重。验收证据包括 POI 样例数据、规则字段说明、数据更新时间展示、风险提示截图和数据来源说明。

\subsection{位置隐私与用户信任风险}

钓鱼用户对野钓点位置非常敏感，如果平台默认公开精确坐标，可能导致用户不愿记录和分享，甚至引发钓点拥挤、生态破坏和用户纠纷。应对措施是在产品设计中将位置权限作为发布核心字段，支持精确公开、模糊公开、好友可见和完全隐藏；后端根据权限返回不同精度坐标，前端只展示授权后的坐标，不在页面隐藏字段中保留精确坐标；社区信息流默认不展示野钓点精确坐标，只有收费钓场、公开水域或用户主动选择精确公开时才展示。对于历史数据，若用户修改可见性，系统应重新计算展示位置。验收证据包括发布页位置权限截图、不同权限账号看到的位置差异截图、接口返回字段对比和隐私说明文本。

\subsection{第三方服务依赖风险}

高德地图、天气服务、DeepSeek、日出日落或潮汐接口均可能出现 Key 配置错误、额度不足、网络超时、返回格式变化和服务不可用。一旦前端直接依赖第三方接口，故障会扩大到页面不可用；一旦 Key 写死在前端，又会产生泄露风险。开发设计已经明确第三方 Key 不进仓库，不写死在代码里，前端不直接写死高德 Key 和 DeepSeek Key，而由后端封装。

应对措施是所有第三方接口由后端代理，设置超时、重试、缓存和降级；地图不可用时展示演示 POI 列表，天气不可用时使用最近一次缓存，AI 不可用时只隐藏解释不影响排序，POI 搜索不可用时保留本地专题钓点。验收证据包括环境变量清单或不含真实密钥的模板、Key 不入库检查、第三方失败模拟截图、降级提示截图和接口日志。

\subsection{推荐与 AI 输出风险}

钓鱼推荐涉及安全和合规，如果模型为了提升体验而忽略禁钓、极端天气或危险水域，就会带来实际风险。AI 解释还可能出现幻觉，例如编造不存在的鱼情、政策或钓点评价。应对措施是坚持规则模型优先，AI 只基于后端给出的结构化结果解释，不允许 AI 自行改变排名；推荐输出必须包含总分、分项分、推荐原因、风险提示和相关 POI 数据；禁钓、限钓和安全风险优先级高于距离和热度；AI 提示词中明确禁止编造来源，无法确认时必须提示用户核验。验收证据包括推荐接口响应样例、禁钓水域降权测试、极端天气降权测试、AI 解释 mock 和真实模式对比、提示词约束说明。

\subsection{数据持久化与并发风险}

当前 MVP 使用 JSON 模拟 NoSQL 数据库，适合课堂 Demo 和单用户演示，但不适合正式多人并发写入。正式版本需迁移数据库。如果继续使用 JSON 承担多人数据写入，可能出现数据覆盖、文件损坏、写入丢失和查询效率低下。

应对措施是课程阶段将 JSON 限定为演示数据，同时给出 PostgreSQL/PostGIS 迁移方案；正式版本将用户、记录、帖子、活动、订单等数据迁移至数据库，图片视频进入对象存储；写接口增加事务控制和唯一性校验；关键操作写入审计日志。课程验收阶段使用 JSON 时，在演示前固定数据、备份数据文件，并避免多人同时写入。验收证据包括数据模型文档、迁移路线说明、备份文件、写入测试结果和数据库方案。

\subsection{账号权限与安全风险}

当前项目仍存在由前端传入 \texttt{user\_id} 的风险，正式架构必须由登录令牌识别当前用户，否则可能出现任意用户读取或修改他人记录、报告、私信和活动报名的问题。应对措施是正式版本引入登录、刷新令牌、当前用户依赖注入、资源所有权校验和管理员权限控制；密码采用安全哈希，不保存明文；敏感接口设置鉴权中间件；日志记录登录失败、异常访问和越权请求；上传文件限制类型、大小和扫描策略；后台管理操作记录审计日志。

课程版本若不完整实现登录，应在投标文件中明确其为 Demo 边界，并在演示环境中限制测试账号和数据范围。验收证据包括权限设计说明、接口鉴权测试计划、越权访问失败截图或安全自查表。

\subsection{内容治理风险}

社区、评论、私信、群聊和活动都可能出现广告、辱骂、违法信息、虚假鱼获、违规钓点引流和危险活动组织。如果没有审核与举报机制，平台很难长期运行。应对措施是对帖子、评论、图片和群消息预留审核状态、举报入口、拉黑机制和管理员处理流程；对活动发布设置组织者信息、活动地点、时间、人数、安全提示和免责声明；对涉及禁钓区或危险水域的帖子自动提示风险；对虚假钓点和争议内容支持用户纠错和管理员复核。

课程阶段可实现基础举报入口和后台审核字段，正式阶段接入内容审核服务。验收证据包括帖子审核字段、举报入口截图、管理员处理流程和活动安全提示模板。

\subsection{进度与范围蔓延风险}

鱼你有图同时涉及地图、社区、记录、AI、活动、装备、会员和报告，如果没有范围控制，容易在有限实习时间内什么都做一点但主链路不稳定。当前阶段应优先稳定 MVP 主链路，复杂商业化能力、权威规则数据合作、生产化数据底座、统一登录和多端账号打通等能力列入后续工程化阶段。

应对措施是以"地图找点—推荐解释—出钓记录—社区发布—个人报告"为 P0 主链路，活动、装备和会员服务作为可演示闭环，真实支付、监管端、商户后台和遥感识别列入后续扩展。项目经理每周检查新增需求，凡影响终验主链路稳定的需求必须延后。验收证据包括需求优先级表、MVP 范围说明、延期需求清单和版本计划。

\subsection{验收表达风险}

技术投标文件如果只写"系统先进、体验良好、智能推荐"，但缺少量化指标、测试证据和边界说明，容易被认为不符合实习要求。应对措施是每一项优势都对应可验证证据，例如推荐接口响应时间、记录字段完整率、帖子关联记录比例、报告生成成功率、位置隐私测试、活动报名签到闭环、订单演示闭环、测试用例通过率等。功能响应表中对已实现、部分实现、待补充和后续规划的功能分开说明，避免把后续规划写成已完成能力。

最终提交前由文档负责人检查编号、页眉、字体、表格、引用、目录和附件一致性。验收证据包括技术评分表、功能响应表、测试报告、演示视频和部署截图。

\subsection{风险管理的总体原则}

通过上述风险管理，本项目把风险从"答辩时被问到再解释"前移到"投标文件中主动说明并给出措施"。这符合真实工程投标的基本逻辑：风险并不可怕，可怕的是不识别、不分级、不设责任人、不留验收证据。本项目将以风险清单作为项目管理文档之一，在每周例会中更新状态，对高风险项设置责任人和截止时间，对无法在本期解决的风险明确降级策略和后续路线。
