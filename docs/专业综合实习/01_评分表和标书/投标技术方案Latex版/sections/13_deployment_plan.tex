\section{部署与运行方案}

本项目"鱼你有图"拟采用"移动端应用 + 后端服务 + 空间数据服务 + 第三方能力封装 + 运维监控"的部署模式。平台面向钓鱼爱好者提供地图找点、禁钓规则提示、鱼情推荐、鱼获记录、社区分享、教程学习、活动报名和会员报告等服务，因此部署方案不能只满足页面可访问，还必须保证空间位置服务稳定、用户出钓记录可持续保存、第三方接口调用安全、异常情况下可降级运行。根据现有开发设计，项目当前采用 Vue 3/Uni-app 作为移动端与小程序端开发基础，后端采用 FastAPI 提供统一 API，地图能力接入高德 JS API，天气、POI、AI 解释等能力通过后端进行封装，第三方密钥不得写死在前端代码中，推荐排序由后端规则模型先完成，AI 只负责解释生成。该责任边界能够降低密钥泄露风险，也能避免 AI 输出直接影响业务排序结果。

\subsection{环境划分}

正式部署时，系统划分为开发环境、测试环境、预生产环境和生产环境四类。开发环境用于小组成员本地调试，前端通过 \texttt{npm install} 和 \texttt{npm run dev} 启动，后端通过 Python 3.11、\texttt{requirements.txt} 和 \texttt{uvicorn app.main:app} 启动，环境变量统一放置在 \texttt{.env} 文件中；测试环境用于接口联调、功能测试和验收前缺陷修复；预生产环境用于模拟真实域名、真实地图 Key、真实对象存储和生产级数据库配置；生产环境用于正式运行。

现有项目文档中已说明，当前 MVP 阶段根目录 \texttt{data/} 使用 JSON 模拟 NoSQL 数据库，每个 \texttt{.json} 对应一个集合，每个 \texttt{.schema.json} 对应集合字段说明；但正式运行阶段，JSON 文件只作为初始化演示数据和导入模板，不再承担多人并发写入职责。正式生产环境建议采用 PostgreSQL/PostGIS 存储钓点、鱼获、用户、帖子、活动、订单等结构化数据，采用 Redis 进行热点 POI、天气摘要、推荐结果和登录会话缓存，采用对象存储保存鱼获图片、视频、报告长图和用户头像，采用 Nginx 进行静态资源托管、HTTPS 终止、反向代理和 gzip/brotli 压缩。

\subsection{生产部署拓扑}

生产部署的基本拓扑为：用户通过微信小程序、H5 或 App 访问前端页面；前端页面访问网关域名；Nginx 将 \texttt{/api} 请求转发至 FastAPI 服务，将静态资源请求转发至前端构建产物，将图片与视频访问转发至对象存储或 CDN；FastAPI 负责业务接口、权限校验、推荐计算、AI 解释封装、地图配置下发和第三方接口代理；数据库负责长期数据沉淀；Redis 负责缓存和异步任务状态；日志系统记录接口调用、异常堆栈、用户关键操作与第三方调用结果。

第三方能力包括高德地图、高德 Web 服务、天气服务、日出日落/潮汐数据、DeepSeek 或其他大模型解释接口。所有第三方 Key 均通过服务端环境变量配置，并由后端提供受控接口给前端使用，不允许出现在 Git 仓库、前端打包文件、公开截图和测试报告中。现有开发设计已经明确，高德 JS API Key 由后端 \texttt{/api/amap/config} 提供，Web 服务 Key 只放在后端环境变量中，DeepSeek Key 通过 \texttt{DEEPSEEK\_API\_KEY} 配置，当前 AI 接口可 mock，后续可切换真实解释生成。

\subsection{容器化与非容器化部署}

为了满足课程实习中"工程交付"的要求，本项目部署不以"能跑"为最低标准，而以"可安装、可配置、可回滚、可观测、可交接"为目标。后端服务采用容器化部署时，可将 FastAPI、Nginx、PostgreSQL、Redis、对象存储适配器分别作为服务模块管理；如果课程验收环境不要求 Docker，则提供非容器化部署脚本，保证评审人员可在 Windows 或 Linux 环境下按部署说明完成启动。

前端构建采用 \texttt{npm run build} 输出静态资源，后端以 \texttt{uvicorn} 或 \texttt{gunicorn + uvicorn worker} 方式运行，生产模式关闭调试日志，启用访问日志、错误日志和接口耗时记录。对于地图、推荐、记录、社区、报告、活动等核心接口，均设置统一超时策略和错误返回格式。

\subsection{降级与容错设计}

系统需要具备模块化降级能力。例如地图 POI 请求失败时，前端展示"地图服务暂时不可用，可查看演示钓点列表"；AI 解释失败时，系统仍返回规则模型排序结果，只将解释部分标记为"暂未生成"；天气接口失败时，采用最近一次缓存天气或提示用户刷新，不影响用户继续记录鱼获。这样的降级设计符合本项目 MVP 边界，也避免把第三方服务不稳定直接转化为平台不可用。

\subsection{运行监控机制}

系统运行期间，平台应建立"应用监控、日志监控、数据备份、异常响应、版本发布"五类运行机制。

应用监控方面，记录 API 平均响应时间、95 分位响应时间、错误率、第三方接口失败率、数据库连接池状态、Redis 命中率、对象存储上传成功率和前端白屏率。对于地图首页、钓点详情、推荐接口、发布接口、社区信息流、报告生成、活动报名和订单演示等核心链路，设置单独指标。

日志监控方面，按用户操作日志、接口执行日志、异常日志、第三方调用日志和安全审计日志分类保存；日志不得记录明文密码、完整第三方密钥和用户精确位置明文，必要时对位置坐标进行权限隔离与脱敏显示。

数据备份方面，数据库每日增量备份、每周全量备份，备份保留不少于 30 天；对象存储开启版本管理或回收站机制；关键配置文件和 \texttt{.env.example} 纳入版本管理，真实 \texttt{.env} 不入库。恢复演练方面，项目上线前至少完成一次"数据库恢复 + 图片访问恢复 + 服务重启"的演练，保证误删数据或服务故障后可在约定时间内恢复核心功能。

\subsection{版本发布与回滚}

版本发布采用"需求冻结—测试构建—预生产验证—生产发布—观察回滚"的流程。每次发布前，产品经理确认需求范围，后端负责人确认数据库迁移脚本，前端负责人确认页面构建产物，测试负责人确认回归测试结果，项目经理确认发布窗口。发布后 30 分钟内重点观察登录、地图、推荐、发布、社区、记录和报告生成接口；若出现核心功能不可用、数据写入异常、用户无法登录、第三方 Key 配置错误或响应时间明显劣化，则启动回滚。

回滚内容包括前端静态包回退、后端镜像回退、数据库迁移回滚或兼容脚本处理。对于数据库字段升级，采用向后兼容原则，新增字段优先设置默认值，不在同一版本中删除旧字段；前端接口调用先保留兼容层，再逐步切换到新字段。现有协作规范中也强调"先改设计书，再改接口，再改页面""接口变更必须先对齐返回结构""新增字段先保证兼容，不要一次性删除旧字段"，该原则将被纳入部署发布制度。

\subsection{运行支撑与交付}

运行支撑方面，本项目承诺提供部署说明、系统操作手册、管理员配置手册、接口说明、数据库初始化脚本、测试账号、演示数据和常见问题清单。针对课堂实习场景，可提供本地单机部署和在线演示部署两套方式：本地单机部署便于老师检查项目代码与架构，在线演示部署便于答辩展示真实交互。针对正式化工程场景，可提供云服务器部署、域名备案说明、HTTPS 证书配置、数据库备份策略和对象存储配置说明。

运行维护期间，平台支持按模块关闭非核心功能，例如真实支付未接入时，装备订单仅保留模拟下单与取消；AI 接口费用超限时，推荐排序继续运行，仅暂停解释生成；活动服务未开放时，地图、记录、社区和报告功能仍可独立运行。通过模块化部署和降级策略，系统能够在课程验收、演示竞赛和后续商业迭代之间保持一致的技术路线，避免为了演示临时写死逻辑，也避免在 MVP 阶段承诺超过团队开发能力的复杂能力。
