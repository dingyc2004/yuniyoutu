\section{核心功能详细设计}

本章逐一展开七个核心功能模块的设计方案，包括目标、输入数据、处理逻辑、输出结果、当前实现状态和验证方式。

\subsection{地图与 POI 模块}

\textbf{模块目标：}让用户在 10 秒内知道附近哪里可以钓。

\textbf{输入数据：}
\begin{itemize}
  \item 用户当前位置（GPS / 手动选择城市）
  \item 筛选条件（类型、鱼种、钓法、费用、设施、夜钓、路亚等）
  \item 高德 POI 搜索结果（当前 MVP 阶段使用 `data/pois.json` 模拟）
\end{itemize}

\textbf{处理逻辑：}
\begin{enumerate}
  \item 前端通过 MapPanel.vue 加载高德 JS API 展示地图，默认围绕武汉示例数据展示钓点，位置选择与手动修正能力由记录位置弹窗承接
  \item 根据视口范围和筛选条件请求 `/api/pois` 接口
  \item 后端从 `pois.json` 加载数据，按距离排序、按条件过滤
  \item 前端渲染 POI 标记和热力表达，风险信息通过 POI 详情与推荐警告呈现；禁钓区面图层作为后续可扩展项
  \item 底部半屏卡片展示附近钓点列表，横滑查看今日推荐
\end{enumerate}

\textbf{输出结果：}地图上的 POI 标记 + 筛选后的钓点卡片列表 + 天气摘要条。

\textbf{当前实现状态：}已实现。HomeView.vue 与 MapPanel.vue 集成高德 JS API 2.0，支持 POI 标记渲染、地图热力表达和关键字搜索。POI 数据当前从 JSON 集合加载，后续可接入高德 POI 搜索 API 和自建垂钓 POI。

\subsection{出钓记录模块}

\textbf{模块目标：}将一次出钓沉淀为可复用的结构化垂钓数据，同时满足用户展示感和成就感。

\textbf{输入数据：}
\begin{itemize}
  \item 用户填写：鱼种、条数、最大单尾重量、总重量、钓法、饵料、装备、钓点
  \item 自动回填：时间段（开竿→收竿）、天气（温度、风力、湿度）、位置（GPS 坐标→地址）
  \item 可选：水情、心情、图片/视频、复盘笔记
\end{itemize}

\textbf{处理逻辑：}
\begin{enumerate}
  \item 用户点击“记一竿”开始计时，前端记录开始时间并持续计时
  \item 收竿时弹出汇总表单：鱼种（标签选择+手动输入）、条数、重量、钓法（台钓/路亚/海钓等）、饵料
  \item 条数为 0 时自动标记为空军记录（\texttt{is\_blank\_trip = true}），允许用户补充空军原因和下次改进计划
  \item 提交后生成战绩摘要卡片（鱼种、数量、重量、钓法、地点按隐私设置显示）
  \item 记录通过 JSON 原子写入持久化，服务重启不丢失
\end{enumerate}

\textbf{输出结果：}结构化出钓记录（FishingRecord）+ 可分享战绩卡片。

\textbf{当前实现状态：}已实现。RecordView.vue 实现开竿计时和收竿汇总弹窗，后端 Pydantic 模型包含鱼种、条数、重量、钓法、饵料、笔记和图片字段，记录通过 `json\_store` 持久化。海钓场景模板（潮汐、风浪、船次等字段）和装备关联（equipment\_ids）已预留但当前为 MVP 阶段暂不展开。

\subsection{社区与发布模块}

\textbf{模块目标：}让鱼获分享可看、可问、可沉淀；同时保护用户精确钓点不被未授权获取。

\textbf{输入数据：}
\begin{itemize}
  \item 帖子内容：标题、正文、图片/视频、发布类型（鱼获/空军/探点/心得）
  \item 关联信息：钓点 POI、出钓记录 ID（可选）
  \item 权限设置：内容权限（公开/私密）+ 位置权限（精确/模糊/隐藏）
\end{itemize}

\textbf{处理逻辑：}
\begin{enumerate}
  \item 用户可从出钓记录一键生成帖子（自动填充鱼获摘要和钓点信息）
  \item 发布时分别选择内容可见性和位置展示粒度
  \item 后端返回公开帖子前执行位置脱敏：精确→保留坐标、模糊→偏移至 1-3 km 范围、隐藏→仅保留城市名
  \item 社区流支持按频道筛选（推荐/同城/话题），排序逻辑结合热度和时间
\end{enumerate}

\textbf{输出结果：}社区帖子（Post）+ 帖子详情页（含互动区、地图位置、相似鱼获推荐）。

\textbf{当前实现状态：}部分实现。PublishView.vue 支持图文发布、关联钓点和权限设置；CommunityView.vue 展示社区流和频道切换；PostViewer.vue 展示帖子详情。帖子与记录的关联（record\_id）已在数据模型中预留。评论/点赞/收藏的后端持久化当前为前端演示，后续将实现完整持久化。

\subsection{推荐与 AI 模块}

\textbf{模块目标：}把复杂数据（天气、位置、鱼情、规则）转成可执行的出钓建议；排序由规则系统控制，AI 负责解释。

\textbf{输入数据：}
\begin{itemize}
  \item 用户位置（经纬度或城市）
  \item 可选：目标鱼种、钓法偏好
  \item 当前天气结构化数据（温度、风力、湿度、天气状况）
  \item 候选 POI 列表（搜索范围内的平台钓点数据）
\end{itemize}

\textbf{处理逻辑：}
\begin{enumerate}
  \item 规则模型计算候选 POI 的六维评分：
  \begin{itemize}
    \item 鱼情分（0.25）：近 7/30 天鱼获数量、鱼种匹配度、空军率
    \item 合规分（0.25）：是否禁钓区、是否禁渔期、限钓规则
    \item 距离分（0.15）：用户到 POI 的距离和预计耗时
    \item 天气适配分（0.15）：当前天气对目标鱼种和钓法的适宜程度
    \item 设施便利分（0.10）：停车、厕所、补给、安全
    \item 社交热度分（0.10）：收藏数、评论数、近期打卡数
  \end{itemize}
  \item 硬性拦截（直接排除或降权）：
  \begin{itemize}
    \item 位于明确禁钓区 → 不推荐，仅展示合规提醒
    \item 极端天气预警 → 不推荐户外野钓
    \item 海钓风浪风险高 → 降低排序并显示安全提醒
  \end{itemize}
  \item Top N 候选 POI 的结构化信息传递给 DeepSeek，生成自然语言推荐理由和注意事项
  \item AI 不参与排序，不改写规则模型的评分结果
\end{enumerate}

\textbf{输出结果：}推荐排名列表 + 分项评分 + 推荐理由 + 风险提示 + AI 生成的自然语言建议。

\textbf{当前实现状态：}已实现。推荐接口 `/api/recommendations` 完成六维规则评分和风险惩罚逻辑。AI 接口 `/api/ai/fishing-advice` 已预留结构，在 production 环境配置 `DEEPSEEK\_API\_KEY` 后可调用 DeepSeek；未配置时返回 mock 解释。具体模型由环境变量 `DEEPSEEK\_MODEL` 控制，默认值为 deepseek-chat。个人历史报告当前由后端统计服务生成，不依赖大模型。

\textbf{验证方式：}调用推荐接口 → 检查返回的 score、breakdown、reasons、warnings 字段 → 检查禁钓 POI 是否被排除或标注风险 → 检查 AI 解释是否基于规则输出而非自行编造。

\subsection{个人主页与统计模块}

\textbf{模块目标：}沉淀个人成就，提供可分享的钓鱼生涯数据。

\textbf{输入数据：}用户的所有出钓记录（来自 `data/records.json`）。

\textbf{处理逻辑：}
\begin{enumerate}
  \item 聚合统计：
  \begin{itemize}
    \item 总出钓次数、总鱼获尾数、总重量
    \item 常钓鱼种（按出现频次）
    \item 高频钓点（按访问次数）
    \item 偏好时段（清晨/上午/下午/夜钓分布）
    \item 常见温度区间
    \item 常用钓法
  \end{itemize}
  \item 指标分为两类：
  \begin{itemize}
    \item \textbf{偏好指标}：最常用钓法、最常去时段、最常去水域（按出现次数统计）
    \item \textbf{效率指标}：单位小时鱼获、单位小时重量、空军率（按单位时间产出计算）
  \end{itemize}
  \item 样本少于 5 次时显示“数据积累中”，不输出伪精确结论
  \item 会员报告弹窗支持 Canvas 导出为分享图片
\end{enumerate}

\textbf{输出结果：}个人战绩面板 + 可导出的分享卡片。

\textbf{当前实现状态：}部分实现。MineView.vue 已实现个人战绩展示和会员报告弹窗；后端 report\_service 已提供 `/api/users/\{user\_id\}/profile-summary` 与 `/api/users/\{user\_id\}/reports` 汇总接口，能够计算偏好指标和单位时间效率指标。Canvas 导出为后续可增强能力，多级会员逻辑将在后续统一为单级会员。

\subsection{教程模块}

\textbf{模块目标：}让新手知道下一步学什么、去哪练。

\textbf{输入数据：}教程元数据（标题、分类、难度、阅读时长、关联钓点）。

\textbf{处理逻辑：}
\begin{enumerate}
  \item 教程按分类组织：新手入门、钓法教程（台钓/路亚/海钓）、鱼种攻略、场景攻略（水库/河道/海边）、装备百科、安全合规
  \item 教程详情页展示关键结论（3-5 条要点）→ 步骤讲解（图文/视频）→ 常见错误 → 适用钓点推荐
  \item 用户收藏某教程后，首页推荐更适合练手的近距离钓点
  \item 后续根据用户记录短板推荐相关教程
\end{enumerate}

\textbf{输出结果：}教程列表 + 教程详情 + 关联练习钓点。

\textbf{当前实现状态：}已实现。TutorialsView.vue 展示教程列表，支持按入门/进阶和图文/视频筛选。当前教程内容为静态 JSON 数据，学习进度跟踪和个性化推荐为后续扩展方向。

\subsection{活动与社群模块（后续规划）}

\textbf{模块目标：}围绕真实出钓场景组织同城约钓、比赛和社群活动。

\textbf{设计要点：}
\begin{itemize}
  \item 活动最小闭环：活动列表 → 详情（组织者、城市、水域、时间、人数、费用、安全要求）→ 报名 → 取消报名 → 签到
  \item 报名成功后自动加入活动群
  \item 活动结束后可生成一条个人活动履历或出钓记录
  \item 群聊 MVP 使用轮询接口，暂不引入 WebSocket
\end{itemize}

\textbf{当前实现状态：}后续规划。PPT 已将同城约钓、比赛、拼船和活动群作为核心能力，但当前 MVP 阶段尚未开发对应代码。相关数据集合（events、event\_registrations、groups、group\_members、messages）已规划，将在后续路线中实现。
