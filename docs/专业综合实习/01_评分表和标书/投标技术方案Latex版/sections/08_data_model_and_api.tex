\section{数据模型与接口设计}

本章说明平台当前 MVP 阶段采用的 JSON 集合数据模型、字段结构和 API 接口规范。当前实现以根目录 \texttt{data/} 下的 \texttt{.json} 文件模拟 NoSQL 集合，并为每个集合提供同名 \texttt{.schema.json} 字段说明；正式多人使用时，可在不改变主要业务对象的前提下迁移到 PostgreSQL/PostGIS、Redis 和对象存储。

\subsection{当前数据设计原则}

当前数据层围绕“地图找点、规则推荐、出钓记录、社区分享、教程学习、活动服务和报告统计”组织，设计原则如下：

\begin{enumerate}
  \item \textbf{集合清晰：}钓点、记录、帖子、教程、活动、订单、消息、报告等业务对象分别保存为独立 JSON 集合，避免所有数据混在单一文件中。
  \item \textbf{字段可验证：}每个集合配套 \texttt{.schema.json}，说明核心字段含义、类型和示例，便于评审人员对照接口返回结果检查。
  \item \textbf{写入可恢复：}后端 \texttt{json\_store.py} 使用临时文件与原子替换写入，降低写入中断导致文件损坏的风险。
  \item \textbf{关联轻量化：}集合间通过 \texttt{id}、\texttt{user\_id}、\texttt{poi\_id}、\texttt{record\_id} 等字段建立引用关系，当前阶段不引入数据库外键。
  \item \textbf{扩展不混淆：}PostgreSQL/PostGIS、Redis、对象存储和统一鉴权属于正式工程化阶段能力，本期文档只给出迁移映射，不把它们写成当前已接入能力。
\end{enumerate}

\subsection{接口规范}

接口响应统一采用“业务数据 + 元信息”的结构。列表接口返回 \texttt{data} 数组和 \texttt{meta} 元信息；详情接口返回单个 \texttt{data} 对象；创建接口成功时返回新建对象并使用 HTTP 201 状态码；删除接口成功时返回 HTTP 204。错误响应统一包含错误码、错误信息和请求路径，便于前端展示和后端排查。

\begin{lstlisting}[caption={列表接口返回结构示例},label={lst:list-response}]
{
  "data": [
    {
      "id": "poi_wh_001",
      "name": "东湖磨山水域",
      "score": 86
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "page_size": 20
  }
}
\end{lstlisting}

分页参数统一采用 \texttt{page}、\texttt{page\_size}；筛选参数按模块扩展，例如 POI 接口支持 \texttt{city}、\texttt{keyword}、\texttt{lat}、\texttt{lng}、\texttt{radius\_m}，帖子接口支持 \texttt{channel}、\texttt{post\_type}，记录接口支持 \texttt{user\_id}。当前 Demo 阶段部分写接口仍通过请求体或查询参数携带 \texttt{user\_id}；正式工程化阶段应改为由登录令牌识别当前用户，并在服务层校验资源所有权。
