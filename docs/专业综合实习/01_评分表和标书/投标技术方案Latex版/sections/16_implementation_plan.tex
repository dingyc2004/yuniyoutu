\section{项目实施计划}

本项目实施计划采用 120 个自然日完成终验的总体节奏，并设置七个阶段。样例技术规范书要求合同签订后 30 个自然日内完成系统需求分析和框图设计，90 个自然日内完成系统上线并开始试运行，120 个自然日内完成终验；本项目以该节奏作为课程技术投标文件的进度框架，使计划既符合真实招投标文档语言，也便于老师检查阶段成果。由于本项目已有产品计划、功能设计和开发设计，实施重点不是从零开始构思，而是将已有 Demo 整理为可部署、可测试、可验收、可交接的工程版本。各阶段安排见表 \ref{tab:milestones}。

\subsection{阶段一：项目启动与范围确认（第 1—10 天）}

项目组召开启动会，明确项目目标、验收口径、人员分工、沟通机制、代码仓库、文档目录、命名规范和提交节奏。产品负责人整理需求清单，将前两份投标文件中的项目概述、需求分析、总体技术方案、系统架构、业务流程、功能响应表、数据模型、推荐模型、技术选型、安全隐私等内容转化为待开发和待验证任务。

项目经理建立需求跟踪表，字段包括需求编号、需求名称、来源章节、优先级、实现状态、负责人、接口依赖、测试用例、验收证据和备注。技术负责人完成当前代码审查，确认哪些功能已经实现、哪些功能属于 Demo、哪些功能需要补齐，特别关注真实高德凭据、登录鉴权、数据库迁移、活动闭环、订单闭环、测试覆盖、部署说明等风险点。该阶段输出《项目启动记录》《需求跟踪表》《人员分工表》《版本计划表》和《风险初始清单》。

\subsection{阶段二：需求分析与总体设计（第 11—30 天）}

该阶段完成系统需求规格说明、原型完善、概要设计、数据库设计、接口设计和部署设计。产品负责人根据用户主链路梳理页面，包括地图首页、钓点详情、发布页、社区页、教程页、我的页、会员报告、活动服务、装备服务和消息入口；后端负责人整理 API，包括 POI 查询、钓点详情、推荐排序、天气快照、帖子列表、帖子发布、出钓记录、会员报告、教程进度、活动报名、活动签到、订单演示等；数据负责人统一数据模型，明确 POI、Record、Catch、Post、User、Report、TutorialProgress、Activity、Order 等对象的字段、主键、外键或关联字段；安全负责人设计权限、位置隐私、内容审核和密钥管理方案。

该阶段必须完成系统架构图、数据流程图、业务流程图和接口清单，保证后续开发不会边做边改方向。对于当前尚未纳入 MVP 的完整支付、正式商户后台、监管端大屏、遥感识别等能力，应在需求规格中明确列入"后续扩展"，不纳入本期验收，以控制范围蔓延。

\subsection{阶段三：后端与数据基础开发（第 31—55 天）}

后端团队优先完成 FastAPI 结构整理、Pydantic Schema 校验、统一错误返回、环境变量读取、第三方服务封装和 JSON 数据持久化加固。当前课程 MVP 继续使用根目录 \texttt{data/} 下的 JSON 集合，保证数据写入有备份机制、字段有 schema 说明、演示数据稳定；SQLite 或 PostgreSQL/PostGIS 迁移方案作为后续工程化设计，不作为本期必须完成项。

推荐服务在本阶段完成规则模型接口，输出总分、分项分、推荐原因、风险提示和关联 POI 数据；AI 解释服务在本阶段完成 mock 与真实接口双模式，保证无 Key 时可演示，有 Key 时可切换真实生成。记录服务完成开竿、收竿、鱼获明细、天气快照、图片字段和社区发布关联；活动服务完成列表、报名、取消报名、签到、履历和从活动生成出钓记录；教程服务完成学习中、完成等状态写入；订单演示服务完成下单、订单列表、模拟支付和取消订单。实施阶段需要将这些 Demo 闭环整理为稳定接口和测试用例，而不是仅停留在页面演示。

\subsection{阶段四：前端页面与交互开发（第 46—75 天）}

前端团队围绕"地图找点—详情—推荐—记录—报告—社区—服务"的主链路进行页面完善，与后端开发存在部分并行。地图页需要支持搜索、筛选、POI 标记、钓点卡片、天气摘要和推荐提示；钓点详情页需要展示基本信息、鱼情分、合规分、距离分、天气适配分、设施便利分、社交热度分和风险提示；发布页需要支持鱼获、空军、探点和教程心得等类型，至少保证鱼种、数量、重量、钓法、饵料、地点、天气和位置权限可录入；社区页需要展示推荐流、同城流、话题流、帖子详情、点赞评论收藏入口；我的页需要展示个人记录、收藏、战绩摘要、报告生成和报告推荐；服务页需要展示活动、群聊和装备入口。

前端还要处理加载状态、错误状态、空状态和弱网状态，避免演示时只要一个接口失败就出现白屏。对于高德底图不可用的情况，保留内置演示地图或钓点列表，保证课堂展示不受 Key 配置影响。

\subsection{阶段五：系统联调与上线试运行（第 76—90 天）}

该阶段将前后端部署到测试环境，使用统一域名和真实或模拟第三方配置进行联调。项目组按验收主链路执行端到端测试，包括新用户进入地图、查看钓点、获得推荐、开始记录、收竿保存、生成报告、发布社区、查看教程、报名活动、签到、形成活动履历、下单装备演示。

测试负责人每天汇总缺陷，按严重程度分为阻断、严重、一般和建议四类；阻断缺陷必须当天或次日修复，严重缺陷必须在试运行结束前清零，一般缺陷可纳入终验前优化，建议类缺陷进入后续版本。项目经理在第 90 天形成《试运行报告》，内容包括已完成功能、待优化功能、测试数据、缺陷统计、性能结果、安全自查和下一阶段计划。样例技术规范书中要求 90 天上线试运行，该阶段就是对该节点的响应。

\subsection{阶段六：质量加固与验收准备（第 91—105 天）}

该阶段重点补齐测试、文档、安全和部署。测试方面完成单元测试、接口测试、端到端测试、性能测试和兼容性测试；文档方面完成部署说明、用户手册、管理员手册、接口文档、JSON 集合字段说明、测试方案、测试用例、测试报告和培训材料；安全方面完成密钥检查、权限边界检查、位置隐私检查、基础 XSS 自查、日志脱敏检查和备份恢复演练；部署方面完成本地运行说明、环境变量清单或模板、初始化数据和演示账号。

该阶段还需要完成一次正式彩排，按答辩顺序演示，不允许现场临时修改数据；如果某功能仍未稳定，应从主链路中降级为"后续规划"，不要在终验时强行展示不稳定能力。

\subsection{阶段七：终验交付（第 106—120 天）}

项目组提交源代码、源代码说明书、部署说明、测试报告、操作手册、培训材料、项目总结报告和演示视频。终验会议中，项目经理先说明项目建设目标和完成情况，产品负责人演示核心业务链路，技术负责人说明系统架构、接口、部署与安全，测试负责人说明测试结果和缺陷闭环，运维负责人说明部署、备份、监控和后续维护。

若老师提出问题，项目组以需求跟踪表和功能响应表为依据回答：已实现功能现场演示，待补充功能说明路线和风险，不属于本期范围的能力说明边界。样例技术规范书要求实施结束后移交全部技术文档，源代码和开发成果也需要交付；本项目在课程场景中同样以"代码 + 文档 + 测试 + 演示"作为完整交付，而不是只提交一份说明材料。
