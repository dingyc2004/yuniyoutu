# 当前项目代码与架构差距复核

> 对照《商业PPT逐页内容与中国市场调研》，复核日期：2026-06-14

## 一、当前已能支撑的核心叙事

项目已经能完整演示“先记录，再连接，后服务”的主链路：

1. **先记录**
   - 一键开竿计时、定位、天气和收竿汇总。
   - 钓鱼过程中逐条记录鱼种、重量、长度和上鱼时间。
   - 现场笔记仅保存到本次出钓记录，收竿后可选择发布到社区。
   - 个人主页汇总出钓数据，会员可生成月报、年报和生涯报告。

2. **再连接**
   - 社区帖子可关联真实出钓记录，并分别设置内容权限和位置权限。
   - 用户可以关注、加好友、私聊和进入活动群聊。
   - 顶部消息入口已有活动提醒、钓友互动和报告提醒等演示内容。

3. **后服务**
   - 地图展示硬编码钓点 POI 和钓友活跃热力，高德凭据不可用时仍能演示。
   - “服务”入口提供同城活动报名、活动群入口和装备消费入口。
   - 装备卡展示真实使用次数、代表战绩和合作商家，符合“记录验证消费决策”的商业逻辑。

## 二、比赛演示前仍建议补齐的 P0 项

### 1. 配置真实高德 Web 端凭据

当前代码已接入 AMap POI Marker 与 HeatMap 插件，但真实高德底图仍依赖：

```env
AMAP_JS_API_KEY=
AMAP_SECURITY_CODE=
```

还需在高德控制台配置本地和部署域名白名单。没有凭据时展示的是产品内置演示地图，不是真实高德底图。

### 2. 增加登录鉴权和数据权限

当前请求仍由前端传入 `user_id`。正式架构必须由登录令牌确定当前用户，避免任意用户读取或修改他人记录、私信、报告与活动报名。

建议增加：

- 登录与刷新令牌
- 当前用户依赖注入
- 记录、帖子、私信、报告的所有权校验
- 管理员审核与操作审计

### 3. 将活动闭环补到签到和履历

目前已支持活动列表、报名和进入群聊，但还缺：

- 取消报名
- 用户端签到入口
- 活动结束后的活动履历
- 从活动一键生成出钓记录
- 活动评价与安全事件反馈

### 4. 将消费入口补到订单闭环

当前“查看并购买”是演示入口。正式商业闭环仍缺：

- `merchants`、`products`、`orders`、`payments`、`refunds` 集合
- 商家认证和商品上下架
- 购物车、订单状态和售后
- 平台佣金与活动服务费结算
- 装备与真实出钓记录的可核验关联

## 三、产品能力仍缺少的 P1 项

### 地图与钓点

- 钓点目前是硬编码数据，缺少用户共建、纠错、审核与可信度评分。
- 缺少禁钓规则来源、规则更新时间和规则变更通知。
- 缺少按鱼种、钓法、时间窗口筛选热力图。
- 缺少轨迹记录、离线地图和导航失败降级。

### 记录与报告

- 单条鱼获尚未支持真实照片上传、图片压缩和对象存储。
- 缺少水情、潮汐、风浪、船次、船长、费用等海钓表单。
- 现场离线记录与服务端同步还没有冲突处理。
- 前端报告仍保留部分本地计算，应完全以服务端报告快照为准。

### 社群

- 好友当前为演示用即时通过，缺少申请、接受、拒绝、拉黑与举报流程。
- 私信和群聊使用普通 HTTP，请求后刷新，不具备 WebSocket 实时推送。
- 缺少未读数、已读状态、消息撤回、图片消息与内容审核。
- “关注”和“同城”信息流仍需改为服务端查询与推荐。

### 教程与推荐

- 教程收藏和完成状态尚未真正写入 `learning_progress`。
- 会员报告尚未根据用户短板跳转到对应教程、活动和装备。
- 推荐算法目前以规则和硬编码为主，缺少解释、反馈和效果评估。

## 四、工程架构仍缺少的 P1 项

- JSON 文件存储适合比赛 Demo，不适合多人并发写入；正式版本需迁移数据库。
- 社交和活动接口仍使用原始 `dict` 请求体，应补充 Pydantic Schema 校验。
- 缺少前端 Vitest 与 Playwright 端到端测试。
- 缺少统一的加载、错误、重试和离线状态管理。
- 前端主包仍超过 1 MB，应按地图、报告、聊天和服务页面动态加载。
- 缺少日志、指标、异常监控、数据备份与隐私数据删除能力。

## 五、推荐的后续架构路线

1. **比赛演示稳定性**：配置高德凭据，补活动签到与订单演示，增加一条完整 E2E 演示测试。
2. **数据与安全**：引入登录鉴权、PostgreSQL、对象存储和所有权校验。
3. **社群实时化**：好友申请、未读消息、WebSocket、内容审核和举报。
4. **商业闭环**：商家、商品、订单、支付、退款和平台结算。
5. **数据驱动增长**：把报告结果真正连接教程、活动和装备推荐，并跟踪转化。

当前版本已经足以向评委证明产品定位和商业闭环，但应明确说明：地图热力、社交关系、活动报名和装备购买目前属于可操作 Demo，真实上线仍需完成鉴权、审核、支付与数据库迁移。

## 六、2026-06-14 本轮完善结果

本轮继续完成了以下闭环：

- 活动支持报名、取消报名、现场签到和个人活动履历。
- 已签到活动可一键生成出钓记录，重复操作不会重复创建记录。
- 教程收藏、学习中和完成状态已写入 `learning_progress`。
- 会员报告新增教程、活动和装备推荐理由，并可直接跳转至对应功能页。
- 活动创建、报名、签到、群消息和教程进度请求已使用 Pydantic Schema 校验。
- 后端自动化测试覆盖活动闭环、教程进度和服务推荐。
- 装备服务新增演示订单闭环，支持下单、订单列表、模拟支付和取消订单；不涉及真实资金。

对应差距状态更新：

- “活动签到与履历”：已完成 Demo 闭环。
- “从活动一键生成出钓记录”：已完成。
- “教程收藏和完成状态持久化”：已完成。
- “报告跳转至教程、活动和装备”：已完成规则推荐版。
- “订单演示闭环”：已完成；真实支付、退款与商家结算仍未接入。
- 仍未完成：活动评价与安全反馈、真实支付与退款、登录鉴权、WebSocket、对象存储和数据库迁移。
