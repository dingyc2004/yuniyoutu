# 鱼你有图开发设计书

## 1. 项目定位

“鱼你有图”是面向钓鱼爱好者的垂钓 GIS 社交平台。它不是通用地图，也不是纯社区，而是把“地图找点、规则判断、鱼情推荐、鱼获发布、社区分享、教程学习”串成一条完整出钓链路。

平台的核心目标是回答钓鱼用户的五个高频问题：

1. 去哪钓
2. 能不能钓
3. 现在适不适合钓
4. 钓到了怎么分享和复盘
5. 新手怎么快速上手

## 2. MVP 范围

当前阶段只做 MVP，不做大而全平台。

### 2.1 MVP 必做

- 地图首页
- 钓点 POI 列表与详情
- POI 规则推荐
- 鱼获/空军发布
- 社区鱼获流
- 教程页
- AI 推荐解释

### 2.2 非 MVP 范围

- 会员系统
- 赛事系统
- 复杂商户系统
- 遥感识别
- 正式禁渔区数据合作
- 完整数据库和权限体系
- 统一登录和多端账号打通

## 3. 前后端分工

### 3.1 前端职责

- 负责 Vue3 页面和交互
- 负责高德 JS API 地图展示
- 负责 POI 点击、详情弹窗、发布表单、社区流展示
- 负责将用户操作提交到后端接口
- 负责轻量本地兜底展示

### 3.2 后端职责

- 负责统一 API 入口
- 负责 POI、帖子、推荐、天气、AI 解释接口
- 负责规则模型排序
- 负责第三方服务封装
- 负责环境变量读取与密钥管理
- 负责向前端返回稳定结构化数据

### 3.3 责任边界

- 前端不直接写死高德 Key、DeepSeek Key
- 后端不直接承担 UI 逻辑
- AI 只做解释，不直接决定推荐排序
- 推荐排序必须由规则模型先算完，再交给 AI 解释

- 展示附近 POI
- 支持关键字搜索、类型筛选

- 地图主体
- 推荐提示条
- POI 卡片列表

- 展示推荐理由

详情字段：

- 基本信息
- 鱼情分
- 合规分
- 距离分
- 天气适配分
- 设施便利分

### 4.3 PublishPage / 发布页

核心作用：

- 发布鱼获
- 发布空军

发布字段：

- 发布类型
- 标题
- 正文

- 鱼种
- 图片或视频
- 定位信息
- 可见性

### 4.4 CommunityPage / 社区页

核心作用：

- 展示鱼获流
- 展示空军复盘
- 展示热帖和互动数据

页面内容：

- 推荐流
- 同城流
- 话题流
- 帖子点赞、评论、收藏入口

- 给新手提供学习入口

内容结构：

- 分类标签

## 5. 后端模块

### 5.1 `app/main.py`

职责：

- 初始化 FastAPI
- 注册 CORS
- 挂载所有 router
- 暴露统一 `/api` 前缀

### 5.2 `app/api/routes_poi.py`

职责：

- `GET /api/pois`
- `GET /api/pois/{poi_id}`

说明：

- 当前先用根目录 `data/pois.json`
- 后续可接高德 POI 和自建垂钓 POI 数据

### 5.3 `app/api/routes_posts.py`

职责：

- `GET /api/posts`
- `POST /api/posts`
- `GET /api/feed`
- `POST /api/catches`

说明：

- 初始数据读取根目录 `data/posts.json`
- 新发布内容当前写入进程内内存列表
- 先保证发布和社区流闭环

### 5.4 `app/api/routes_recommend.py`

职责：

- `POST /api/recommendations`

说明：

- 后端规则模型完成排序
- AI 不直接参与排序
- 返回 Top 3 推荐和解释依据

### 5.5 `app/api/routes_weather.py`

职责：

- `GET /api/weather/current`
- `GET /api/weather`

说明：

- 当前可 mock
- 预留高德天气服务封装

### 5.6 `app/api/routes_ai.py`

职责：

- `POST /api/ai/fishing-advice`

说明：

- 当前返回 mock 解释
- 若配置 `DEEPSEEK_API_KEY`，保留 httpx 真实调用结构
- AI 只解释推荐结果，不改排序

### 5.7 `app/core/config.py`

职责：

- 用 `pydantic-settings` 统一读取环境变量
- 管理高德 Key、DeepSeek Key、环境模式、前端来源

### 5.8 `app/schemas/`

职责：

- 定义稳定数据结构
- 让前后端字段对齐

重点模型：

- `FishingPOI`
- `CatchPost`
- `Recommendation`
- `WeatherSnapshot`

### 5.9 `app/services/`

职责：

- 聚合业务逻辑
- 封装推荐计算
- 封装天气转换
- 封装高德和 DeepSeek 预留调用

### 5.10 根目录 `data/`

职责：

- 提供 MVP 期 JSON 集合数据
- 每个 JSON 文件代表一个集合
- 每个集合都有对应的 `.schema.json` 描述文件
- 支撑前端首轮联调

当前集合：

- `data/pois.json`
- `data/posts.json`
- `data/tutorials.json`
- `data/weather_snapshots.json`

当前集合描述：

- `data/pois.schema.json`
- `data/posts.schema.json`
- `data/tutorials.schema.json`
- `data/weather_snapshots.schema.json`

## 8. 推荐策略

推荐排序由后端规则模型完成，AI 只做解释。

### 8.1 分数构成

- 鱼情分
- 合规分
- 距离分
- 天气适配分
- 设施便利分
- 社交热度分

### 8.2 规则原则

1. 禁钓、限钓、安全风险必须优先提示。
2. 极端天气优先降权。
3. 近距离不等于高分，必须结合鱼情和合规判断。
4. 商业钓场在设施分上可适当加权。
5. 路亚、翘嘴等目标关键词可以影响鱼情分，但不能覆盖禁钓风险。

### 8.3 输出要求

推荐结果必须包含：

- 排名
- 总分
- 分项分
- 推荐原因
- 风险提示
- 相关 POI 数据

## 9. 第三方服务接入方式

### 9.1 高德地图

- 前端使用高德 JS API
- 高德 JS API Key 由后端 `/api/amap/config` 提供
- Web 服务 Key 只放后端环境变量里
- 安全码通过 `AMAP_SECURITY_CODE` 配置

### 9.2 高德 Web 服务

- POI 和天气后续可通过后端服务封装接入
- 当前 MVP 先使用 JSON 集合模拟数据，确保可跑通

### 9.3 DeepSeek

- 通过 `DEEPSEEK_API_KEY` 配置
- 当前 AI 接口默认 mock
- 后续可切换为真实解释生成

## 10. 环境配置方式

### 10.1 后端

使用 conda + `requirements.txt`：

```bash
conda create -n yuniyoutu-backend python=3.11
conda activate yuniyoutu-backend
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

### 10.2 前端

```bash
cd frontend
npm install
npm run dev
```

### 10.3 环境变量

放在项目根目录 `.env`，模板见 `.env.example`。

### 10.4 模拟数据

根目录 `data/` 使用 JSON 模拟 NoSQL 数据库。每个 `.json` 是一个集合，每个 `.schema.json` 是对应集合的语言无关字段说明。

## 11. 小组协作规范

1. 先改设计书，再改接口，再改页面。
2. 接口变更必须先对齐返回结构，避免前端和后端同时大改。
3. 新增字段先保证兼容，不要一次性删除旧字段。
4. 前端先保留旧接口兼容层，再逐步切换到新接口。
5. 第三方 Key 不进仓库，不写死在代码里。
6. 每次合并前先检查页面、接口和文档是否同步。
7. MVP 期间优先保证“地图找点 -> 详情 -> 推荐解释 -> 发布 -> 社区展示”闭环。
