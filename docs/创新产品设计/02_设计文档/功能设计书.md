# 鱼你有图移动端功能设计书

> 基于《产品创新计划书》整理。本文档面向 Uni-app / Vue 移动端、小程序端与后端接口设计，重点回答五个核心问题：如何记录鱼获、如何学习钓鱼、如何发现钓点 POI、如何体现社交属性、如何基于位置与天气推荐附近钓点。

## 1. 产品定位与核心闭环

### 1.1 产品一句话定义

“鱼你有图”是面向钓鱼爱好者的垂钓 GIS 社交平台：用地图解决“去哪钓、能不能钓、有没有鱼”，用鱼获记录和社区互动解决“晒成果、学经验、找同好”。

### 1.2 核心用户需求

| 用户需求 | 产品承接方式 | 对应一级入口 |
| --- | --- | --- |
| 记录一次钓鱼成果 | 鱼获发布、出钓日志、轨迹/天气/钓点自动绑定 | 发布、社区、我的 |
| 学习钓鱼教程 | 新手路径、鱼种/钓法/装备教程、POI 场景教程 | 教程 |
| 发现钓鱼 POI | 地图找点、附近钓点、筛选、钓友贡献 POI | 地图 |
| 社交分享渔获 | 关注流、话题、钓友评论、战绩卡片、外部分享 | 社区、发布 |
| 基于天气地理推荐钓点 | 定位、天气、历史鱼获、规则、DeepSeek 生成建议 | 地图、推荐 |

### 1.3 产品闭环

1. 用户打开 App，首页地图根据当前位置展示附近钓点与今日鱼情。
2. 用户查看钓点详情，判断距离、鱼种、收费、禁钓规则、近期鱼获和钓友评价。
3. 系统根据天气、位置、历史鱼获和钓点属性生成推荐，帮助用户决定去哪里钓。
4. 用户出钓后发布鱼获或空军日志，自动沉淀鱼种、钓法、时间、天气、位置等结构化数据。
5. 鱼获进入社区流和钓点详情页，成为其他用户判断该钓点的依据。
6. 数据积累后提升推荐准确度，形成“用户记录 -> 数据沉淀 -> 更好推荐 -> 更多出钓 -> 更多记录”的增长闭环。

## 2. 移动端信息架构

### 2.1 底部导航建议

| Tab | 名称 | 核心作用 | 关键页面 |
| --- | --- | --- | --- |
| 1 | 地图 | 找钓点、看附近、看推荐 | 地图首页、筛选、POI详情、路线 |
| 2 | 社区 | 看鱼获、互动、话题 | 推荐流、关注流、同城、话题 |
| 3 | 发布 | 记录鱼获或空军 | 选择照片、填写钓况、隐私设置 |
| 4 | 教程 | 新手学习与进阶 | 新手路线、钓法、鱼种、装备 |
| 5 | 我的 | 战绩、收藏、会员 | 出钓记录、收藏钓点、个人报告 |

### 2.2 首页优先级

首页建议采用“地图即首页”，而不是纯信息流首页。原因是产品差异点来自 GIS 和 POI，打开即回答用户最关心的“附近哪里能钓”。

首页首屏结构：

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 顶部搜索 | 搜索钓点、水库、河流、钓场、鱼种 | 输入联想、历史搜索、热门地点 |
| 地图主体 | POI 标记、禁钓区图层、鱼获热力、当前位置 | 缩放、拖动、点选 POI |
| 浮动筛选 | 野钓、钓场、免费、夜钓、路亚、可停车 | 多选筛选，结果实时刷新 |
| 今日推荐卡 | “今天适合去的 3 个钓点” | 横滑查看、进入推荐理由 |
| 快捷发布 | “记一竿”悬浮按钮 | 直接进入鱼获记录 |

## 3. 功能一：钓鱼成果记录与鱼获发布

### 3.1 设计目标

鱼获记录不能只是普通帖子。它必须同时满足两件事：

1. 给用户足够强的展示感和成就感。
2. 把一次出钓沉淀为可复用的结构化垂钓数据。

### 3.2 发布入口

| 入口 | 场景 | 默认发布类型 |
| --- | --- | --- |
| 底部中间“发布” | 主动晒鱼获 | 鱼获记录 |
| 地图 POI 详情页“在这里钓过” | 补充某钓点数据 | 钓点鱼获 |
| 我的记录“补记一次” | 出钓后回填 | 出钓日志 |
| 社区话题页“参与话题” | 参与活动或比赛 | 话题鱼获 |

### 3.3 发布流程

#### 第一步：选择记录类型

页面标题：`记一竿`

可选类型：

| 类型 | 适用场景 | 页面表现 |
| --- | --- | --- |
| 鱼获 | 钓到鱼，晒成果 | 照片优先，战绩卡片突出 |
| 空军 | 没钓到鱼，也想记录 | 支持自嘲模板和原因复盘 |
| 探点 | 去了一个新钓点 | 强调位置、环境、规则 |
| 教程心得 | 分享经验 | 进入长图文编辑模式 |

#### 第二步：上传照片/视频

交互设计：

- 支持 1-9 张照片，首图作为社区封面。
- 支持 15-60 秒短视频，用于展示上鱼过程、钓点环境。
- 读取照片 EXIF 的时间和位置，但必须弹出隐私确认。
- 如果照片无定位，允许用户手动选择钓点或使用当前位置。

隐私保护：

| 位置展示方式 | 说明 |
| --- | --- |
| 精确公开 | 显示具体 POI，适合收费钓场或公开水域 |
| 模糊公开 | 只显示 1-3 公里范围，适合野钓点 |
| 仅好友可见 | 关注关系或互关后可见 |
| 完全隐藏 | 只展示城市/区县，不进入钓点数据统计 |

#### 第三步：填写鱼获信息

字段建议：

| 字段 | 必填 | 输入方式 | 说明 |
| --- | --- | --- | --- |
| 钓点 | 是 | 自动定位/搜索/地图点选 | 绑定 POI 或新建临时 POI |
| 鱼种 | 是 | 标签选择+手动输入 | 鲫鱼、鲤鱼、翘嘴、黑鱼、鲈鱼等 |
| 数量 | 否 | 数字输入 | 可填尾数 |
| 最大单尾重量 | 否 | 数字+单位 | 斤/kg 可切换 |
| 总重量 | 否 | 数字+单位 | 用于战绩统计 |
| 钓法 | 是 | 标签 | 台钓、路亚、海钓、矶钓、筏钓等 |
| 饵料/拟饵 | 否 | 标签+文本 | 玉米、蚯蚓、亮片、米诺等 |
| 装备 | 否 | 选择/文本 | 鱼竿、线组、钩型 |
| 时间段 | 是 | 自动+可改 | 清晨、上午、下午、夜钓 |
| 天气 | 自动 | API 回填 | 天气、温度、风力、湿度 |
| 水情 | 否 | 标签 | 涨水、落水、浑水、清水 |
| 心情 | 否 | 表情/标签 | 爆护、小爽、空军、跑鱼 |

#### 第四步：生成鱼获战绩卡

发布前生成可分享卡片：

| 卡片元素 | 说明 |
| --- | --- |
| 主图 | 用户鱼获照片 |
| 战绩标题 | 如“今晚翘嘴 6 尾，最大 3.2 斤” |
| 地点 | 按隐私设置显示 |
| 天气 | 温度、风力、气压/湿度 |
| 钓法 | 路亚/台钓等 |
| 成就标签 | 首钓、破纪录、爆护、空军也光荣 |
| App 水印 | 鱼你有图 Logo 和二维码 |

卡片用于站内帖子封面，也用于微信、朋友圈、小红书等外部分享。

### 3.4 鱼获详情页

页面模块：

| 模块 | 内容 | 目的 |
| --- | --- | --- |
| 顶部媒体 | 图片/视频轮播 | 展示成果 |
| 战绩摘要 | 鱼种、数量、重量、钓法 | 快速判断内容价值 |
| 钓况信息 | 时间、天气、水情、饵料、装备 | 结构化复盘 |
| 地图位置 | POI 卡片或模糊区域 | 引流到钓点详情 |
| 作者说明 | 心得、过程、注意事项 | 社交表达 |
| 互动区 | 点赞、评论、收藏、追问、分享 | 社交沉淀 |
| 相似鱼获 | 同钓点/同鱼种/同钓法 | 增强浏览深度 |

### 3.5 “空军”也要可记录

很多钓鱼社交只强调大鱼获，但空军同样有数据价值。设计上要避免用户觉得“没钓到就没法发”。

空军发布字段：

- 钓点
- 时间段
- 钓法
- 饵料
- 天气
- 水情
- 空军原因自评：天气不行、水位变化、选点失误、鱼不开口、人太多、被网工影响
- 下次改进计划

空军帖的价值：

- 帮助其他用户避坑。
- 增强社区真实感。
- 为推荐算法提供负样本。

## 4. 功能二：钓鱼教程

### 4.1 设计目标

教程模块要解决新手“看了很多内容但不知道从哪开始”的问题。内容不应只是信息流，而应是结构化学习路径。

### 4.2 教程首页

页面结构：

| 区域 | 内容 |
| --- | --- |
| 顶部学习目标 | 新手入门、路亚入门、台钓入门、海钓入门 |
| 今日推荐 | 根据用户位置、季节、鱼种热度推荐教程 |
| 学习路径 | 从装备、找点、调漂、选饵、识鱼到安全 |
| 热门问题 | “新手第一根竿怎么买”“野钓怎么找水深” |
| 附近适用教程 | 基于附近 POI 的场景教程 |

### 4.3 教程分类

| 分类 | 内容示例 | 目标用户 |
| --- | --- | --- |
| 新手入门 | 基础装备、线组、钓鱼安全、常见术语 | 新手 |
| 钓法教程 | 台钓、路亚、海钓、矶钓、筏钓 | 进阶用户 |
| 鱼种攻略 | 鲫鱼、鲤鱼、草鱼、翘嘴、黑鱼、鲈鱼 | 有目标鱼用户 |
| 场景攻略 | 水库、河道、黑坑、海边、防波堤 | 出行决策用户 |
| 天气鱼情 | 气压、风向、温差、潮汐、日出日落 | 进阶用户 |
| 装备百科 | 竿、轮、线、钩、饵、浮漂 | 消费决策用户 |
| 安全合规 | 禁渔期、禁钓区、文明垂钓、救生 | 全体用户 |

### 4.4 教程详情页

教程详情页建议使用“短内容 + 图示 + 相关钓点”的结构：

| 模块 | 设计 |
| --- | --- |
| 标题区 | 标题、难度、预计阅读时间 |
| 关键结论 | 3-5 条要点先给答案 |
| 步骤讲解 | 图文/短视频分步骤 |
| 常见错误 | 新手容易踩坑的点 |
| 适用钓点 | 推荐附近适合练习该技巧的 POI |
| 相关鱼获 | 展示真实用户用该方法钓到的记录 |
| 练习任务 | 如“本周完成一次调漂记录” |

### 4.5 教程与社区联动

- 教程下方展示“用这个方法钓到的鱼获”。
- 用户发布鱼获时选择钓法后，系统可反向推荐相关教程。
- 新手用户收藏某教程后，首页推荐更适合练手的近距离钓点。
- 教程作者可认证为“钓法达人”，形成内容创作者体系。

## 5. 功能三：钓鱼 POI 发现

### 5.1 POI 类型

平台不应只存“地点”，而要存“垂钓语义增强 POI”。

| POI 类型 | 示例 | 关键字段 |
| --- | --- | --- |
| 野钓点 | 河流、水库、湖泊、桥下、水闸 | 是否禁钓、鱼种、可达性、安全风险 |
| 商业钓场 | 黑坑、斤塘、练竿塘 | 收费、营业时间、放鱼信息、预约 |
| 海钓点 | 防波堤、码头、礁石、船钓基地 | 潮汐、风浪、安全等级 |
| 渔具店 | 饵料、装备、补给 | 营业时间、品牌、距离 |
| 停车/补给点 | 停车场、厕所、便利店 | 距离钓位、步行路线 |
| 禁钓/限钓区 | 保护水域、禁渔区 | 规则来源、生效时间、处罚提示 |

### 5.2 地图图层

| 图层 | 表达方式 | 价值 |
| --- | --- | --- |
| 钓点点位 | 不同图标区分野钓/钓场/海钓 | 快速找点 |
| 鱼获热力 | 近 7/30/90 天热度 | 判断有没有鱼 |
| 禁钓区 | 红色透明面图层 | 避免违规 |
| 风险区 | 黄色提示，如深水、陡坡、浪大 | 安全提醒 |
| 商户图层 | 钓场、渔具店、补给 | 商业转化 |
| 路线图层 | 步行入口、停车点、导航线 | 到达效率 |

### 5.3 POI 详情页

页面信息分层：

| 层级 | 内容 | 目的 |
| --- | --- | --- |
| 头部 | 名称、类型、距离、评分、收藏 | 快速识别 |
| 状态条 | 今日推荐指数、是否可钓、天气摘要 | 立即决策 |
| 核心信息 | 鱼种、钓法、收费、开放时间、夜钓 | 判断适配 |
| 地图与路线 | 导航、停车、入口、步行距离 | 解决怎么去 |
| 近期鱼获 | 近 7/30 天鱼获列表 | 判断有没有鱼 |
| 规则说明 | 禁渔期、限竿、限钩、路亚限制 | 合规 |
| 钓友评价 | 环境、水质、人流、口碑 | 社会验证 |
| 贡献纠错 | 补充鱼种、更新规则、举报错误 | 众包维护 |

### 5.4 POI 可信度机制

每个 POI 应有“可信度”，避免野钓点被随意污染。

可信度来源：

| 来源 | 加分逻辑 |
| --- | --- |
| 官方/商户认领 | 最高可信 |
| 多名用户打卡 | 中高可信 |
| 鱼获照片带定位 | 中高可信 |
| 高德 POI 匹配 | 基础可信 |
| 用户手动新增 | 初始低可信 |
| 被多人举报错误 | 降低可信 |

可信度等级：

- A：已认证，信息可靠。
- B：多人验证，基本可靠。
- C：新点位，需更多验证。
- D：争议点位，谨慎参考。

### 5.5 POI 新增与纠错

新增流程：

1. 用户在地图长按或发布鱼获时选择“新增钓点”。
2. 选择类型：野钓点、商业钓场、海钓点、补给点、风险点。
3. 填写名称、鱼种、钓法、是否收费、是否禁钓、现场照片。
4. 系统检查附近是否已有重复 POI。
5. 新点进入“待验证”状态。
6. 后续通过多人打卡、鱼获绑定、管理员审核提升可信度。

纠错内容：

- 位置错误
- 已禁钓
- 已关闭
- 收费变化
- 鱼种变化
- 危险提醒
- 重复点位合并

## 6. 功能四：社交属性与渔获分享

### 6.1 社区结构

社区不建议做成泛论坛，而应围绕鱼获、钓点、教程、话题展开。

| Feed | 内容 | 排序逻辑 |
| --- | --- | --- |
| 推荐 | 鱼获、探点、教程、热门话题 | 兴趣、位置、互动 |
| 关注 | 已关注钓友内容 | 时间倒序 |
| 同城 | 当前城市/附近内容 | 距离+热度 |
| 钓点动态 | 收藏钓点的新鱼获 | 时间+可信度 |
| 话题 | 活动、挑战、鱼种专题 | 热度 |

### 6.2 社交关系

| 关系 | 说明 |
| --- | --- |
| 关注 | 单向关注钓友 |
| 互关好友 | 可见更精确钓点或私密动态 |
| 钓点同好 | 收藏同一钓点的用户弱关系 |
| 城市圈子 | 同城钓友聚合 |
| 钓法圈子 | 路亚、台钓、海钓等兴趣圈 |

### 6.3 互动动作

| 动作 | 设计重点 |
| --- | --- |
| 点赞 | 轻量表达认可 |
| 评论 | 支持追问“什么饵”“几点开口” |
| 收藏 | 收藏鱼获、教程、钓点 |
| 追问 | 钓鱼垂类问题模板，降低评论成本 |
| 分享 | 生成战绩卡或钓点卡 |
| 约钓 | 对互关或同城用户开放 |
| 送漂/打赏 | 后期可做内容激励 |

### 6.4 分享模板

分享模板要有“炫耀感”，同时不泄露敏感地点。

模板类型：

| 模板 | 场景 |
| --- | --- |
| 爆护战绩卡 | 大量鱼获 |
| 破纪录卡 | 最大单尾或新品种 |
| 空军复盘卡 | 没钓到但有趣 |
| 钓点推荐卡 | 分享公开钓场 |
| 比赛成绩卡 | 活动/赛事 |

卡片默认不展示精确经纬度，只显示用户选择的地理粒度。

### 6.5 话题与活动

建议首期话题：

- #今日鱼获
- #空军也要发
- #同城找钓友
- #新手第一条鱼
- #路亚翘嘴挑战
- #周末去哪钓
- #文明垂钓打卡

活动玩法：

| 活动 | 规则 | 产品价值 |
| --- | --- | --- |
| 城市鱼获榜 | 按城市统计本周鱼获 | 拉动同城活跃 |
| 鱼种挑战 | 指定鱼种打卡 | 增强内容主题 |
| 钓点探路官 | 贡献 POI 和纠错 | 冷启动数据 |
| 空军文学大赛 | 空军帖互动排名 | 降低发布门槛 |
| 文明垂钓积分 | 垃圾带走、规则提醒 | 公共服务价值 |

## 7. 功能五：附近钓点查询与智能推荐

### 7.1 附近钓点查询

入口：

- 地图首页自动展示附近 5-20 公里钓点。
- 搜索框输入地点或鱼种。
- 筛选按钮选择野钓、收费钓场、海钓、夜钓、路亚等。
- 教程页点击“附近适合练习的钓点”。

筛选条件：

| 条件 | 示例 |
| --- | --- |
| 距离 | 3km、5km、10km、20km、自定义 |
| 类型 | 野钓、钓场、海钓、渔具店 |
| 鱼种 | 鲫鱼、鲤鱼、翘嘴、黑鱼、鲈鱼 |
| 钓法 | 台钓、路亚、海钓、夜钓 |
| 费用 | 免费、收费、会员价 |
| 设施 | 停车、厕所、夜灯、餐饮 |
| 规则 | 可夜钓、可路亚、无禁钓风险 |
| 鱼情 | 近 7 天有鱼获、近 30 天热度高 |

### 7.2 推荐结果展示

推荐列表卡片字段：

| 字段 | 表达 |
| --- | --- |
| 推荐指数 | 0-100 分，颜色分级 |
| 推荐理由 | “距离近、近 7 天有 12 条鱼获、风力适中” |
| 风险提示 | “疑似禁渔期”“夜间不建议独自前往” |
| 主鱼种 | Top 3 鱼种 |
| 近期鱼获 | 近 7/30 天数量 |
| 路线信息 | 距离、预计耗时、停车情况 |
| 操作 | 收藏、导航、查看详情 |

### 7.3 推荐评分模型

推荐分采用“规则模型 + LLM 解释”的方式，不应让大模型直接决定排序。排序由后端可控算法完成，DeepSeek 负责把结构化结果解释成自然语言建议。

基础评分：

```text
推荐分 = 鱼情分 * 0.30
      + 合规分 * 0.25
      + 距离分 * 0.15
      + 天气适配分 * 0.15
      + 设施便利分 * 0.10
      + 社交热度分 * 0.05
```

各分项说明：

| 分项 | 输入数据 | 说明 |
| --- | --- | --- |
| 鱼情分 | 近 7/30 天鱼获、鱼种匹配、空军率 | 判断有没有鱼 |
| 合规分 | 禁渔期、禁钓区、限钓规则 | 不可钓直接降为 0 |
| 距离分 | 用户位置到 POI 距离、预计耗时 | 越近越高，但不绝对 |
| 天气适配分 | 天气、温度、风力、湿度、潮汐 | 针对鱼种和钓法计算 |
| 设施便利分 | 停车、厕所、补给、安全 | 新手权重更高 |
| 社交热度分 | 收藏、评论、近期打卡 | 判断活跃度 |

硬性拦截：

- 位于明确禁钓区：不推荐，只显示合规提醒。
- 商业钓场已关闭：不推荐。
- 极端天气预警：不推荐户外野钓。
- 海钓风浪风险高：降低排序并显示安全提醒。
- 用户未授权定位：改用手动城市或搜索位置。

### 7.4 天气与地理位置推荐逻辑

推荐流程：

1. 获取用户当前位置，经纬度转行政区。
2. 调用高德周边 POI 搜索，召回水域、钓场、渔具店、停车等基础 POI。
3. 查询平台自有垂钓 POI 数据，合并去重。
4. 调用天气接口获取当前区域天气和预报。
5. 读取平台历史鱼获、空军记录、禁钓规则、商户状态。
6. 计算候选钓点推荐分。
7. 将 Top N 钓点的结构化信息传给 DeepSeek，生成“推荐理由”和“注意事项”。
8. 前端展示推荐卡，允许用户查看详情或导航。

### 7.5 DeepSeek 智能建议设计

DeepSeek 用于生成自然语言建议、解释推荐原因、总结出钓计划。不要让它直接接触用户密钥，也不要把用户隐私数据原文传给模型。

建议接口由后端调用：

```text
POST /api/ai/fishing-advice
```

请求参数：

| 字段 | 说明 |
| --- | --- |
| user_level | 新手/普通/老手 |
| user_location | 模糊位置或城市，不传精确住址 |
| target_fish | 目标鱼种 |
| fishing_method | 钓法 |
| weather | 天气结构化数据 |
| candidate_pois | 推荐算法筛出的候选 POI |
| rule_warnings | 禁钓/限钓/风险提示 |
| history_summary | 用户历史偏好摘要，不传完整隐私记录 |

模型输出 JSON：

```json
{
  "summary": "今天更适合选择近岸缓流和有近期鱼获的钓点。",
  "top_recommendations": [
    {
      "poi_id": "p_001",
      "reason": "距离近，近7天有多条鲫鱼鱼获，风力较小，适合台钓新手。",
      "risk": "傍晚人流较多，建议提前占位。"
    }
  ],
  "avoid": [
    {
      "poi_id": "p_009",
      "reason": "规则信息显示当前处于禁钓期，不建议前往。"
    }
  ],
  "tips": ["带足照明和防滑鞋", "优先选择蚯蚓或腥香饵"]
}
```

系统提示词建议：

```text
你是一个谨慎的垂钓出行助手。你只能基于输入的结构化天气、位置、钓点、历史鱼获和规则数据给出建议。
如果存在禁钓、极端天气、安全风险，必须优先提示风险，不得鼓励用户违规或冒险。
输出必须是 JSON，不要编造不存在的鱼获、法规或商户信息。
```

当前 DeepSeek 官方文档显示 API 基础地址为 `https://api.deepseek.com`，聊天接口为 `/chat/completions`，当前模型列表包含 `deepseek-v4-flash` 和 `deepseek-v4-pro`；旧的 `deepseek-chat` 和 `deepseek-reasoner` 标注将于 2026-07-24 废弃。因此本项目建议：

| 场景 | 模型 |
| --- | --- |
| 实时推荐解释 | deepseek-v4-flash |
| 个人历史钓鱼报告 | deepseek-v4-pro |
| 社区内容摘要 | deepseek-v4-flash |

### 7.6 高德地图 API 接入设计

根据高德开放平台文档，可使用以下能力：

| 能力 | 用途 | 建议接口 |
| --- | --- | --- |
| 搜索 POI 2.0 | 搜索水库、河流、钓场、渔具店等 | `/v5/place/text`、周边搜索能力 |
| 天气查询 | 根据 adcode 获取当前/未来天气 | `/v3/weather/weatherInfo` |

注意：

- 当前工作目录中的 `deepseek.txt` 和 `高德key.txt` 文件存在但为空，需要在真实开发环境中补充密钥，并由后端读取为环境变量。

## 10. 权限、隐私与合规

### 10.1 权限申请

| 权限 | 使用场景 | 申请时机 |
| --- | --- | --- |
| 定位 | 附近钓点、天气、推荐 | 首次进入地图页 |
| 相册 | 发布鱼获 | 点击上传图片时 |
| 相机 | 拍摄鱼获 | 点击拍摄时 |
| 通知 | 收藏钓点鱼情、评论回复 | 用户收藏或互动后 |

### 10.2 隐私策略

- 精确钓点默认不公开，用户主动选择后才公开。
- 野钓点默认使用模糊位置，防止过度曝光造成资源压力。
- 照片 EXIF 信息读取前必须提示。
- 用户可随时修改历史帖的位置可见范围。
- AI 推荐只传必要结构化字段，不传用户原始隐私文本。

### 10.3 合规策略

- 禁钓区、禁渔期、保护水域要作为最高优先级规则。
- 不确定规则不能写成“可钓”，只能写“规则未知，建议核实”。
- 用户发布违规内容时，系统提示并限制推荐曝光。
- 与地方政策相关内容需要保留来源、更新时间和可信度。

## 13. 关键设计结论

1. 首页必须是地图，社区是第二增长场，而不是第一入口。
2. 鱼获发布必须结构化，否则无法支撑 POI 和推荐。
3. 空军记录必须被鼓励，它是鱼情判断的重要负样本。
4. POI 的核心竞争力不是“地图上有点”，而是每个点有垂钓语义、近期鱼情和规则可信度。
5. DeepSeek 应作为解释层和建议层，排序和合规判断必须由后端规则系统控制。
6. 精确钓点隐私必须谨慎处理，尤其是野钓点。
7. MVP 应先跑通“找点 -> 推荐 -> 出钓 -> 发鱼获 -> 反哺钓点”的闭环。
