《鱼你有图》报告功能表述校对建议

校对依据：当前仓库 Vue3 + Vite 前端组件、FastAPI 后端路由、data JSON 集合与已有测试文件。
总体判断：报告的大方向基本正确，但有几类表述需要调整：一是“移动应用”应更准确写成“移动端 Web 演示应用”；二是社区、活动、装备并非只停留在原型，已有可操作 Demo 与后端接口；三是照片上传、真实短视频、后台管理、登录鉴权、实时聊天、真实支付等能力尚未完整实现，不能写成已完成。


一、3.1.1 功能总体结构

原文：
本项目已经实现移动应用的首页地图钓点查询、图文钓鱼记录、钓鱼教程视频/图文集合、钓鱼活动页面和装备展示页面等功能，并完成钓鱼佬社区原型设计。社区原型支持用户发布图文帖子或短视频，集成钓友加好友、私聊和群聊能力。

问题：
当前项目是 Vue3 + Vite 的移动端 Web Demo，不是原生移动 App。社区也不只是静态原型，已经有帖子、关注、好友、私信、群聊等前后端 Demo；但短视频主要是“视频格式/封面/信息流形态”演示，没有真实视频上传和播放。

建议改为：
本项目已经实现面向移动端浏览场景的 Web 演示应用，包含首页地图钓点查询、出钓记录、钓鱼教程、同城活动、装备服务和钓友社区等模块。社区模块已支持图文动态和视频形态动态的发布演示，并接入关注、好友申请、私聊和群聊等基础社交流程；其中视频内容、图片上传和实时通信仍以 Demo 交互为主，尚未接入真实媒体上传与 WebSocket 实时推送。


二、3.1.2 核心功能清单：首页地图钓点查询

原文：
地图定位、水域与钓点检索、钓点卡片展示、路线入口、规则/天气/鱼情信息入口。当前完成状态：已实现移动端页面与主要查询流程。

问题：
地图、搜索、POI 点位、天气展示、适钓指数和钓点卡片已实现；POI 数据中包含风险、规则、设施、鱼情等字段。路线规划能力在 MapPanel 组件中存在，但当前首页没有形成清晰的用户入口；钓点详情页也没有完整展示停车、规则、安全提示和近期记录。

建议改为：
地图点位展示、水域与钓点搜索、钓点卡片、天气/适钓指数、鱼种与热力信息展示；POI 数据包含规则、风险和设施字段，路线规划能力已有组件基础但前端入口仍需完善。当前完成状态：已实现移动端 Web 地图查询 Demo 与主要浏览流程，钓点详情信息展示仍可继续补齐。


三、3.1.2 核心功能清单：图文钓鱼记录

原文：
记录出钓时间、位置、鱼类信息、照片、钓法、饵料、装备和复盘文字，支持有鱼获记录与空军记录。当前完成状态：已实现记录页面与图文内容录入。

问题：
开竿计时、长按收竿、位置选择、天气温度、逐条鱼获、鱼种、重量、长度、钓法、饵料、装备文字、复盘和空军原因已实现；但照片目前是图片数量/占位展示，没有真实文件上传，装备也不是结构化装备选择。

建议改为：
记录出钓开始/结束时间、位置、天气温度、鱼种、条数、重量、长度、钓法、饵料、装备文字和复盘内容，支持逐条鱼获记录与空军记录。当前完成状态：已实现开竿/收竿记录闭环和后端持久化；图片仍为占位数量演示，真实照片上传与结构化装备选择有待完善。


四、3.1.2 核心功能清单：钓鱼教程集合

原文：
提供视频教程和图文教程集合，可按新手入门、钓法技巧、装备使用、安全注意事项等类别组织。当前完成状态：已实现教程展示页面。

问题：
教程不只是展示页，已支持图文/视频、入门/进阶筛选、教程详情、收藏、学习中、完成状态，并通过 learning_progress 持久化。但当前分类口径不是完整的“装备使用、安全注意事项”等固定分类。

建议改为：
提供图文和视频形态的教程内容，支持按图文/视频、入门/进阶筛选，进入教程详情后可收藏、标记学习中或完成，并将学习进度写入后端。当前完成状态：已实现教程展示、详情和学习进度 Demo；更细的装备使用、安全专题分类可作为后续扩展。


五、3.1.2 核心功能清单：钓鱼活动页面

原文：
展示同城约钓、钓场活动、比赛、教学局和装备体验等活动信息，支持活动详情与报名流程预留。当前完成状态：已实现活动展示页面。

问题：
当前活动能力已经超过“展示”和“报名预留”，前端有活动列表、报名、取消报名、签到、活动群入口、活动履历，后端有活动、报名、签到、群消息接口，且已签到活动可以生成出钓记录。

建议改为：
展示同城约钓、教学局等活动信息，支持活动报名、取消报名、现场签到、活动群入口和活动履历；签到后可一键生成活动出钓记录。当前完成状态：已实现活动 Demo 闭环，活动评价、安全反馈和真实组织者后台仍未实现。


六、3.1.2 核心功能清单：装备展示页面

原文：
展示鱼竿、鱼线、鱼钩、饵料、收纳、户外安全装备等内容，支持分类浏览和详情展示。当前完成状态：已实现装备展示页面。

问题：
装备数据和装备列表已实现，页面展示名称、类别、商家、描述、真实使用次数、代表战绩和价格，并支持生成演示订单、模拟支付和取消订单。但当前没有独立装备详情页，也没有明显的分类筛选；支付是模拟支付，不是真实交易。

建议改为：
展示装备名称、类别、商家、适用说明、真实使用次数、代表战绩和价格，并支持生成演示订单、模拟支付和取消订单。当前完成状态：已实现装备服务与订单 Demo；装备详情页、分类筛选、真实支付、退款和商家结算仍未接入。


七、3.1.2 核心功能清单：钓鱼佬社区

原文：
支持图文帖子、短视频帖子、话题标签、点赞、评论、收藏、关注和内容浏览。当前完成状态：已完成原型。

问题：
帖子列表、频道筛选、搜索、图文/视频形态发布、从记录快速填充、帖子详情、作者主页、关注和收藏都已有前端流程；后端也有帖子、评论、点赞/收藏 reaction、关注接口。但是帖子详情中的点赞、评论、收藏有一部分仍是前端本地演示或 localStorage，并非全部通过后端持久化；短视频没有真实视频文件。

建议改为：
支持图文动态和视频形态动态、话题标签、频道筛选、搜索、帖子详情、作者主页、关注、收藏以及点赞/评论演示；后端已提供帖子、评论、互动和关注接口。当前完成状态：已实现社区可操作 Demo，短视频媒体上传、评论/点赞前端全量持久化和内容审核仍需完善。


八、3.1.2 核心功能清单：钓友关系与聊天

原文：
支持加好友、好友列表、私聊、群聊、消息列表和活动群沟通。当前完成状态：已完成原型。

问题：
当前已有社交目录、关注、好友申请/添加、私信列表、发送私信、群聊消息、活动群入口和通知列表。限制是：好友申请接受/拒绝流程不完整，部分前端把好友状态作为演示处理；聊天通过 HTTP 请求读写，不是实时 WebSocket；图片消息、未读状态、撤回、拉黑举报等未实现。

建议改为：
支持钓友列表、关注、好友申请/添加、私聊、群聊、消息列表和活动群沟通的 Demo 流程。当前完成状态：已实现基础社交与聊天接口；好友审核、实时推送、图片消息、未读状态和拉黑举报仍属于后续能力。


九、3.1.3 辅助功能与支撑能力：用户体系

原文：
手机号/第三方登录、个人资料、经验等级、个人主页、历史记录管理。

问题：
当前有 users、memberships 数据集合，有用户资料、经验等级、个人主页、会员状态和历史记录展示；但没有手机号登录、第三方登录或真实鉴权，前端仍通过 demo_user/demo_nonmember 切换演示身份。

建议改为：
已实现 Demo 用户资料、经验等级、会员状态、个人主页、历史记录、我的发布和收藏夹；手机号/第三方登录、登录鉴权和资料编辑仍未接入。


十、3.1.3 辅助功能与支撑能力：位置隐私设置

原文：
精确位置默认私密，公开分享时支持隐藏位置、水域展示、城市展示或模糊范围展示。

问题：
记录保存时 privacy_level 固定为 private，发布页支持内容可见范围和位置精度，后端对公开帖子执行 hidden、city_only、area_blur、precise 脱敏逻辑。表述基本正确，但应说明这是帖子发布层面的隐私能力，且还缺登录鉴权和好友权限校验。

建议改为：
出钓记录默认按私密记录保存；社区发布时可分别设置内容可见范围和位置精度，支持精确、水域模糊、仅城市和隐藏位置，后端会对公开帖子执行位置脱敏。当前仍缺少登录鉴权、好友权限校验和隐私操作审计。


十一、3.1.3 辅助功能与支撑能力：内容互动

原文：
点赞、评论、收藏、关注、转发和举报。

问题：
点赞/评论/关注后端接口存在，收藏主要由前端 localStorage 保存；转发只是提示类交互，举报未看到对应前端入口和后端接口。

建议改为：
支持点赞、评论、收藏、关注和分享提示等互动演示，并提供评论、互动、关注等基础后端接口；举报、内容审核和全量互动持久化仍需补充。


十二、3.1.3 辅助功能与支撑能力：消息通知

原文：
好友申请、私信、群聊、评论回复、活动提醒和记录反馈。

问题：
当前有 notifications 数据集合和通知数量展示，有私信、群聊、活动消息演示；但未实现系统级推送、评论回复通知、好友申请完整通知流和记录反馈闭环。

建议改为：
已实现通知数据读取与消息入口展示，并支持私信、群聊和活动提醒类演示消息；实时推送、评论回复通知、好友申请完整通知流和记录反馈仍需后续实现。


十三、3.1.3 辅助功能与支撑能力：后台管理

原文：
水域 POI 管理、规则信息维护、教程内容管理、活动管理、装备内容管理和社区审核。

问题：
当前有 JSON 数据集合和部分创建接口，但没有后台管理页面，也没有管理员权限、审核流或操作审计。该项不能写成已具备能力。

建议改为：
当前通过 data 目录 JSON 集合维护 POI、规则说明、教程、活动、装备和社区内容，并提供部分前台/接口级创建能力；独立后台管理、社区审核、管理员权限和操作审计尚未实现。


十四、3.1.4 用户核心流程

原文：
用户打开 App 后，首先进入首页地图，查看附近水域、钓点、路线和相关提示；确定出钓后，用户可点击开竿并由系统自动记录时间、位置和环境条件；收竿后补充鱼种、重量、照片、钓法和复盘内容。

问题：
“App”建议改为“应用/移动端 Web 应用”。时间和天气可自动带入，位置需要用户授权、地图选点或手动填写；照片仍不是实际上传。路线能力未形成清晰首页入口。

建议改为：
用户打开移动端 Web 应用后，首先进入首页地图，查看附近水域、钓点、天气、适钓指数和钓点提示；确定出钓后，用户可进入记录页开竿计时，系统记录开始时间并结合天气数据，位置可通过授权定位、地图选点或手动填写补充；收竿后补充鱼种、条数、重量、钓法、饵料、装备和复盘内容，图片部分目前以数量/占位演示为主。


十五、3.1.4 用户核心流程

原文：
记录完成后，用户可以将其保存在个人档案中，也可以选择转化为社区图文或短视频内容。

问题：
记录转图文/视频形态动态是支持的，但“短视频内容”容易被理解为真实视频上传。

建议改为：
记录完成后，用户可以将其保存在个人档案中，也可以一键带入发布页，转化为社区图文动态或视频形态动态；当前视频形态主要用于信息流和详情页演示，尚未接入真实视频上传。


十六、3.2.1 设计理念：记录轻量

原文：
产品将记录拆分为“开竿自动采集”和“收竿补充信息”两个阶段。

问题：
时间自动采集成立，天气可从天气数据带入，位置并非完全自动采集。

建议改为：
产品将记录拆分为“开竿计时采集”和“收竿补充信息”两个阶段：开竿时自动记录开始时间并结合天气信息，位置通过授权定位、地图选点或手动填写完成；收竿后再补充鱼获、钓法、饵料、装备和复盘内容。


十七、3.2.2 外观设计

原文：
整体风格应体现户外、水域和记录感；建议以水域蓝绿色、浅灰地图底色和白色卡片作为基础。

问题：
这段使用“应”“建议”，像设计方案而不是当前实现说明。当前页面实际采用蓝绿、水色、纸感暖色、白色卡片、地图热力色和服务模块深绿等组合。

建议改为：
当前界面整体体现户外、水域和记录感，核心色彩以蓝绿色、水色、浅色卡片和纸感暖色为基础，地图区域叠加热力色，活动与装备模块使用更高识别度的辅助色，以保证首页地图、记录、社区和服务页面之间既统一又有区分。


十八、3.2.3 用户界面设计：首页地图钓点查询页

原文：
展示用户当前位置、附近水域、钓点点位、搜索框、筛选项、底部钓点卡片和开竿入口。关键交互：地图拖拽、点位点击、钓点详情展开、路线跳转、筛选切换。

问题：
当前有地图、搜索、点位、天气、适钓指数、钓点列表和开竿入口；筛选项不明显，路线跳转没有形成完整入口。

建议改为：
展示地图、附近水域与钓点点位、搜索框、天气/适钓指数、钓点列表卡片和开竿入口。关键交互包括地图拖拽、点位点击、搜索钓点、钓点详情查看和进入记录页；筛选切换与路线入口仍可继续完善。


十九、3.2.3 用户界面设计：钓点详情页

原文：
展示钓点名称、距离、常见鱼种、规则提示、天气信息、近期记录、停车/入口说明和安全提示。

问题：
当前详情页主要展示名称、类型、距离、热度、推荐理由、地址、鱼种标签和钓友评论。规则、天气、近期记录、停车/入口、安全提示虽然数据中部分存在，但页面未完整呈现。

建议改为：
展示钓点名称、类型、距离、热度、推荐理由、地址、常见鱼种和钓友评论；POI 数据中已包含规则、风险、设施、鱼情等字段，后续可在详情页进一步补充规则提示、停车/入口、安全提示和近期记录。


二十、3.2.3 用户界面设计：图文钓鱼记录页

原文：
照片上传、位置隐私选择、保存或发布。

问题：
当前记录页没有真实照片上传；位置隐私选择主要在发布页，不在记录保存流程中。

建议改为：
一键开竿、长按收竿、位置选择、逐条鱼获记录、现场笔记、图片数量占位、收竿汇总、保存记录和发布本次鱼获；位置公开精度在发布社区动态时单独选择。


二十一、3.2.3 用户界面设计：活动页面

原文：
展示活动封面、时间、地点、人数、费用、组织者、报名状态和注意事项。

问题：
当前活动卡主要展示标题、费用、人数、描述、水域、时间、报名/签到/取消/活动群；组织者和注意事项未在卡片中完整展示。

建议改为：
展示活动标题、费用、人数、描述、水域地点、活动时间和报名状态，支持立即参与、取消报名、现场签到、活动群和活动履历；组织者信息、注意事项和活动评价可作为后续补充。


二十二、3.2.3 用户界面设计：装备展示页

原文：
按装备类型展示图片、名称、适用场景、基础参数和用户记录关联入口。关键交互：分类筛选、查看详情、收藏、查看相关记录/测评。

问题：
当前装备页没有真实图片、分类筛选、独立详情、收藏或相关记录入口；已实现的是装备列表、使用次数、代表战绩、商家、价格、演示订单和模拟支付。

建议改为：
展示装备类别、名称、商家、说明、真实使用次数、代表战绩和价格，支持生成演示订单、查看订单、模拟支付和取消订单；装备图片、分类筛选、详情页、收藏和相关测评/记录入口仍待完善。


二十三、3.2.3 用户界面设计：聊天与群聊页

原文：
发送文本/图片。

问题：
当前聊天只支持文本消息，未实现图片消息。

建议改为：
加好友、关注、发送文本消息、查看私聊记录、进入活动群聊和发送群聊文本；图片消息、未读状态和实时推送仍待补充。


二十四、3.2.4 交互设计特点：地图卡片联动

原文：
用户点击地图点位后，底部弹出钓点卡片；继续上滑进入详情页。

问题：
当前实现为地图点位弹出 popup，首页底部/列表卡片可点击进入详情页；没有明显的“上滑进入详情页”交互。

建议改为：
用户点击地图点位后展示钓点弹层或进入钓点详情，首页底部钓点列表也可直接打开详情页，从而减少页面跳转并保持地图场景下的判断连续性。


二十五、3.2.4 交互设计特点：图文/短视频双发布

原文：
社区支持图文经验、鱼获日记、空军复盘和短视频内容。

问题：
图文和视频形态发布支持，但短视频没有真实上传和播放。

建议改为：
社区支持图文经验、鱼获日记、空军复盘和视频形态内容发布；当前视频形态主要以封面、信息流和短视频详情页演示为主，后续需要接入真实视频上传、转码、播放和审核。


二十六、3.2.4 交互设计特点：好友与群聊衔接

原文：
用户可从帖子作者主页、活动详情或同城群入口发起好友申请和聊天。

问题：
从作者主页发起关注/好友申请已实现，活动群入口已实现；但从活动详情直接向某个用户发起好友申请并不明显，聊天实时性和好友审核流程不完整。

建议改为：
用户可从帖子作者主页发起关注和好友申请，也可从活动入口进入活动群沟通；当前好友审核、活动成员间直接加好友和实时聊天仍是后续完善方向。
